# 课程内容生成与题库格式规范

本文档是“码战先锋”课程内容生成的统一规范。

适用范围：

- 课程介绍
- 章节正文
- 课时内容
- 章节测验题目
- 对战题目
- 代码阅读题
- 代码填空题
- 后续 Python、JavaScript 等课程内容生成

本文档只描述内容格式和质量要求，不修改 API、TypeScript 内部类型、Prisma schema、migration、seed 逻辑或数据库数据。

## 一、生成原则

每次生成课程内容时，必须同时满足以下目标：

1. 学习者只阅读当前题目即可理解题意。
2. 题目必须有唯一、可验证的答案。
3. 所有代码必须具备完整上下文，不能依赖隐藏变量或未说明的输入。
4. 代码填空题必须有真实代码上下文、可见空白和非空标准答案。
5. 选择题必须有且只有一个正确选项。
6. 解析必须说明正确原因，不能只写“答案是 A”。
7. 难度必须反映真实认知负担，不能通过歧义或冷门知识制造难题。
8. 用于对战的题目必须适合在有限时间内阅读和作答。
9. 课程正文、题干、选项、解析和代码中的术语必须保持一致。
10. 生成完成后必须进行格式自检和内容自检，再交给项目解析器验证。

## 二、当前项目的硬性约束

当前 Python 章节使用 Markdown 源文件和项目内解析器导入。解析器位于：

`server/prisma/seed-data/v1/python-basic-chapter-03.ts`

当前 Python 章节还由对应的 TypeScript wrapper 配置课时 key 和题目 key。现有章节通常配置为：

- 18 道题目

因此，生成现有 Python 章节的内容时，必须先确认该章节 wrapper 中的 `LESSON_KEYS` 和 `QUESTION_KEYS` 数量。不要让生成模型自行增加或减少课时、题目，也不要自行生成不会被项目识别的稳定 key。

如果要新增章节，需要同时准备：

- `docs/python-chapter/python-basic-chapter-XX.md`
- 对应的 `server/prisma/seed-data/v1/python-basic-chapter-XX.ts`
- `python-basic.ts` 中的章节导入和章节顺序
- 对应的 lesson keys 和 question keys
- parser、seed 和题库回归测试

只生成 Markdown 文件并不会自动让新章节进入课程。

## 三、课程文件格式

课程文件应使用 UTF-8 编码，推荐使用 LF 换行。课程级信息使用以下结构：

```markdown
# 课程信息

课程名称：Python 基础入门
课程标识：python-basic
课程分类：BACKEND
编程语言：Python
难度：BEGINNER
预计学习时间：720 分钟
课程简介：面向初学者的 Python 课程简介。
适合人群：没有编程基础、希望系统学习 Python 的学习者。
课程封面：
发布状态：PUBLISHED

---

# 第十六章：章节名称

章节简介：本章要解决的问题和学习价值。
预计学习时间：120 分钟

章节学习目标：
- 能够理解本章的核心概念
- 能够阅读本章范围内的基础代码
- 能够完成本章的练习和对战题
- 能够识别本章常见错误

---
```

字段要求：

- `课程标识` 必须与项目课程 seed 的稳定标识一致。
- `编程语言` 必须与实际代码一致。
- `难度` 只能使用项目支持的课程难度，例如 `BEGINNER`。
- `发布状态` 只有在内容完成并通过验证后才使用 `PUBLISHED`。
- `课程封面：` 可以为空，因为当前内容解析不依赖封面文本。
- 课程名称、章节名称、简介和学习目标不能为空。
- 章节学习目标必须与正文和题目实际覆盖的知识一致。

## 四、课时正文格式

每个课时必须包含课时标题、简介、预计时间和正文。正文块使用项目当前支持的标记：

- `[标题]`
- `[文本]`
- `[代码 language=python] ... [/代码]`
- `[示例 title=...] ... [/示例]`
- `[提示 title=...] ...`
- `[警告 title=...] ...`

标准示例：

```markdown
## 课时 1：读取并处理用户输入

课时简介：学习 input() 的返回值类型，并将输入转换为需要的数据类型。
预计学习时间：20 分钟

### 正文

[标题]
input() 返回什么

[文本]
input() 返回字符串。即使用户输入数字，程序也需要显式转换后才能进行数值运算。

[代码 language=python]
age_text = "18"
age = int(age_text)
print(age + 1)
[/代码]

[示例 title=把输入文本转换为整数]
说明：先读取字符串，再转换为整数并进行计算。
语言：python
age_text = "18"
age = int(age_text)
print(age + 1)
[/示例]

[提示 title=先确认数据类型]
看到 input() 时，先判断当前值是字符串还是已经转换后的数字。

[警告 title=不要把字符串直接当数字相加]
"18" + 1 会导致类型错误，必须先使用 int() 转换。

### 课时题目
```

正文代码要求：

- 代码必须完整、可运行、上下文明确。
- 代码示例默认使用 Python 3 语法。
- 不使用未介绍的第三方库、文件、网络、系统环境或随机结果。
- 不使用 `pass`、`...`、`TODO` 作为示例中的未完成逻辑。
- 示例中出现的变量、函数和模块必须已经定义或导入。
- 输出内容必须能够由读者根据代码直接推导。
- `[代码 language=python]` 必须使用对应的结束标记 `[/代码]`。
- `[示例 title=...]` 必须包含 `说明：`、`语言：` 和完整代码，并使用 `[/示例]` 结束。
- `[提示]` 和 `[警告]` 的正文不能为空。

## 五、选择题格式

选择题使用 `SINGLE_CHOICE`。项目解析器要求至少两个选项，并且只能有一个选项带 `[正确]`。

标准格式：

```markdown
#### 题目 1

题型：SINGLE_CHOICE
题干：下面程序运行后会输出什么？

```python
name = "Python"
print(name.upper())
```

难度：MEDIUM
分值：10
知识点：字符串、方法调用、程序输出
是否用于 Battle：是
Battle 难度：MEDIUM
Battle 展示类型：输出预测

选项：
- A. Python
- B. PYTHON [正确]
- C. name.upper
- D. 程序报错

解析：
upper() 会返回字符串的大写形式，因此输出为 PYTHON。A 保留了原始大小写；C 只是方法引用；D 不符合代码实际执行结果。
```

选择题要求：

- 选项使用 `A`、`B`、`C`、`D` 作为稳定选项标识。
- 至少有两个选项，推荐固定为四个选项。
- 只能有一个选项带 `[正确]`。
- 所有选项必须属于同一个回答维度，例如都填写输出、都填写变量名或都填写行为。
- 错误选项必须具有迷惑性但不能因为题目表达不清而成立。
- 不要把“以上都正确”“以上都不正确”作为默认凑数选项。
- 题干和代码必须包含回答所需的全部信息。
- `SINGLE_CHOICE` 对战题必须提供 `Battle 展示类型`。

支持的对战展示类型：

- `综合项目题`
- `代码用途`
- `代码阅读`
- `代码分析`
- `异常识别`
- `代码纠错`
- `Bug 定位`
- `代码填空`
- `执行流程`
- `输出预测`

## 六、代码填空题格式

代码填空题使用 `CODE_FILL`。当前项目会把题干文本和代码上下文解析为 Battle stem，并要求代码中存在可见的下划线空白。

标准格式：

```markdown
#### 题目 2

题型：CODE_FILL
题干：补全代码，计算列表中所有分数的平均值并输出结果。请填写平均值计算表达式。
难度：HARD
分值：10
知识点：列表、sum、len、表达式
是否用于 Battle：是
Battle 难度：HARD
Battle 展示类型：代码填空

题目代码：
```python
scores = [80, 90, 70]
average = ____
print(average)
```

可接受答案：
```python
scores = [80, 90, 70]
average = sum(scores) / len(scores)
print(average)
```

判题设置：
- 区分大小写：是
- 忽略首尾空格：是
- 保留代码内部空格：是
- 统一 Windows 和 Unix 换行：是

解析：
sum(scores) 得到所有分数的总和，len(scores) 得到元素数量，两者相除即可得到平均值。

标准完整代码：
```python
scores = [80, 90, 70]
average = sum(scores) / len(scores)
print(average)
```
```

代码填空题要求：

- 必须有 `题目代码：` 或可被 parser 识别的 Python 代码块。
- 代码必须包含至少一个可见的 `____`。
- 空白必须对应明确的代码任务，不能只放在空文件中。
- 题干必须说明是填写表达式、语句、字段还是完整代码。
- `可接受答案：` 后至少有一个非空答案。
- 推荐提供两种等价写法，例如单引号和双引号，但不要加入语义不同的答案。
- 按当前题库约定，可接受答案应使用完整最终提交代码，不要只写一个孤立片段。
- `标准完整代码：` 必须是不含 `____`、`pass` 或 `...` 的可运行代码。
- 代码填空题的 `Battle 展示类型` 应使用 `代码填空`，综合项目题才使用 `综合项目题`。
- 不要设计多个空白；后续生成内容优先保持每题一个主要空白，降低判题歧义。

## 七、非对战题格式

`FILL_BLANK` 和 `TRUE_FALSE` 当前不能用于 Battle。

示例：

```markdown
#### 题目 3

题型：FILL_BLANK
题干：Python 中用于计算列表长度的内置函数是 ______。
难度：EASY
分值：10
知识点：列表、内置函数
是否用于 Battle：否

可接受答案：
- `len`
- `len()`

判题设置：
- 忽略首尾空格：是
- 合并连续空格：是

解析：
len() 会返回字符串、列表等对象包含的元素数量。
```

注意：`FILL_BLANK` 不应设置 `是否用于 Battle：是`。`TRUE_FALSE` 必须有两个选项且只能有一个正确选项。

## 八、难度和对战题池规则

题目难度只能使用：

- `EASY`
- `MEDIUM`
- `HARD`

当前对战服务：

- 只读取 `isBattleEnabled = true` 的题目。
- 只接受 `SINGLE_CHOICE` 和 `CODE_FILL`。
- 只接受 `MEDIUM` 和 `HARD`。
- 要求课程、章节和章节测验均为已发布状态。
- 选择题必须至少有两个选项且只有一个正确选项。
- 代码填空题必须有非空 `acceptedAnswers`。
- 每场默认 20 题，目标约为 14 道 MEDIUM 和 6 道 HARD。
- 如果 HARD 题不足，系统会用剩余合格题目补足；如果 Python 题库中没有 HARD，实际对战就会全部变成 MEDIUM。

难度定义：

- EASY：单一概念、短代码、直接判断。
- MEDIUM：两个已学概念组合，需要跟踪变量、执行顺序或常见错误。
- HARD：多个已学概念组合，需要处理边界、数据结构、流程、错误定位或代码设计，但不能依赖没有讲过的知识。

HARD 题不能通过以下方式制造：

- 故意省略关键条件。
- 使用没有解释的库或语法。
- 使用随机数、时间、网络、文件或系统环境造成不确定结果。
- 让多个选项都合理。
- 依赖 Python 版本差异而不说明版本。
- 使用很长但没有学习价值的代码。
- 使用与当前章节无关的高级知识。

## 九、内容质量门禁

生成模型输出后，必须逐题检查：

- 题干非空且语义完整。
- 题干不依赖图片、前文或隐藏上下文。
- 代码变量全部有定义。
- 函数和模块全部可用。
- 输入值已给出，或题目明确说明输入内容。
- 输出可以唯一确定。
- 选择题只有一个正确答案。
- 代码填空有上下文、有 `____`、有完整 accepted answer。
- 解析与实际运行结果一致。
- 解析没有复制错误答案或使用互相矛盾的说法。
- 题目没有空选项、空解析、空代码或占位文本。
- 不存在 `TODO`、`待补充`、`略`、`同上`、`自行思考` 等未完成内容。
- 题目中的技术术语与正文保持一致。
- 对战题可以在有限屏幕空间内阅读和完成。

禁止使用容易造成不确定性的示例：

```python
import random
import time
input()
open("本地文件.txt")
requests.get("https://example.com")
```

除非题目已经完整提供输入、文件内容、环境和预期行为，否则不要使用这些代码。

## 十一、导入前验证顺序

内容生成完成后，不要直接执行生产 seed。推荐顺序：

1. 保存到正确的 `docs` 源文件。
2. 检查章节文件名和现有 wrapper 配置是否一致。
3. 运行 seed content parser 测试。
4. 检查题目总数、Battle 数量、MEDIUM 数量和 HARD 数量。
5. 检查所有 CODE_FILL 的 stemBlocks 和 acceptedAnswers。
6. 检查所有 Battle 题的 `battlePresentation` 是否被正确解析。
7. 对现有题库更新时，优先使用稳定 identity 的 targeted updater。
8. 确认不会删除旧题或重建 Question ID。
9. 通过 dry-run 后，再单独审计生产更新范围。
10. 没有明确批准前，不执行生产 seed、数据库写入或 deploy。
