# 码站先锋 MVP 功能范围与验收清单

文档版本：V1.0
适用版本：码站先锋 V1.0 MVP
文档用途：开发范围控制、Codex任务拆分、功能测试与阶段验收
前置文档：`01-产品需求文档-PRD.md`

---

# 1. 文档目的

本文档用于进一步明确码站先锋第一版的功能边界，并将产品需求拆解为可开发、可测试、可验收的任务。

本文档重点回答以下问题：

1. 第一版必须开发哪些功能。
2. 每项功能做到什么程度才算完成。
3. 哪些功能明确不在第一版中开发。
4. Codex应按照什么顺序完成任务。
5. 用户如何判断功能是否真正可用。

第一版开发过程中，应优先保证核心流程完整，不追求功能数量。

---

# 2. MVP核心目标

码站先锋 V1.0 MVP 必须完成以下核心闭环：

```text
用户登录
→ 学习Python课程
→ 完成章节小测
→ 参加练习或人机对战
→ 查看答题结果
→ 错题进入错题本
→ 返回课程复习
```

除上述核心闭环外，第一版增加基础校园互助和管理后台，用于验证社区交流和内容管理能力。

# 5. M01 项目基础架构

## 5.1 功能范围

需要建立三个独立项目：

```text
code-pioneer/
├── miniapp/      微信小程序前端
├── server/       NestJS后端
├── admin-web/    Vue管理后台
├── docs/         项目文档
└── deploy/       部署配置
```

技术栈：

### 微信小程序

```text
原生微信小程序
TypeScript
WXML
WXSS
```

### 后端

```text
Node.js
NestJS
TypeScript
Prisma
PostgreSQL
```

### 管理后台

```text
Vue 3
TypeScript
Vite
Element Plus
```

## 5.2 必须完成内容

* [ ] 创建统一项目根目录。
* [ ] 创建 `miniapp` 目录。
* [ ] 创建 `server` 目录。
* [ ] 创建 `admin-web` 目录。
* [ ] 创建 `docs` 目录。
* [ ] 创建 `deploy` 目录。
* [ ] 配置统一 `.gitignore`。
* [ ] 创建 `.env.example`。
* [ ] 创建根目录 `README.md`。
* [ ] 初始化 Git 仓库。
* [ ] 后端可以启动。
* [ ] 管理后台可以启动。
* [ ] 小程序可以在微信开发者工具中运行。
* [ ] 后端能够连接 PostgreSQL。
* [ ] Prisma迁移可以执行。
* [ ] 前端能够调用后端测试接口。

## 5.3 验收标准

1. 三个项目均可独立启动。
2. 根目录结构符合约定。
3. 不存在真实密码或密钥。
4. 后端提供健康检查接口：

```text
GET /api/health
```

5. 健康检查正常返回：

```json
{
  "success": true,
  "data": {
    "status": "ok"
  }
}
```

6. 管理后台能成功调用健康检查接口。
7. 小程序能成功调用健康检查接口。
8. 数据库连接失败时，后端输出明确错误。

## 5.4 不包含内容

本模块不开发：

* 课程。
* 用户业务。
* 对战。
* 社区。
* 管理功能。

* [ ] 管理员账号表。

```text

POST /api/auth/logout

POST /api/admin/auth/login
GET  /api/admin/auth/me
POST /api/admin/auth/logout
```

## 6.6 验收标准

1. 首次登录会创建一个用户账号。
2. 同一微信用户重复登录不会创建多个账号。
3. 未登录用户不能访问受保护接口。
4. 令牌无效时返回明确错误。
5. 被禁用用户无法进行受保护操作。
6. 管理员密码不能以明文保存。
7. 普通用户令牌不能访问管理员接口。
8. 内容管理员不能访问超级管理员专属接口。
9. 微信AppSecret不得出现在小程序代码中。
10. 日志中不得输出完整访问令牌。

# 9. M05 章节小测

## 9.1 功能范围

支持题型：

* 单选题。
* 判断题。
* 代码输出选择题。
* 填空题。
* 代码输入题。

## 9.2 必须完成内容

* [ ] 获取章节小测。
* [ ] 展示题目。
* [ ] 展示选项。
* [ ] 展示代码块。
* [ ] 记录用户选择。
* [ ] 检查是否完成所有题目。
* [ ] 提交答案。
* [ ] 服务端判断正误。
* [ ] 创建小测记录。
* [ ] 创建答题明细。
* [ ] 计算正确率。
* [ ] 返回答案解析。
* [ ] 错题加入错题本。
* [ ] 支持再次测试。

## 9.3 核心接口

```text
GET  /api/v1/chapters/:chapterId/quiz
POST /api/v1/quizzes/start
POST /api/v1/quizzes/:attemptId/submit
GET  /api/v1/quizzes/:attemptId/result
```

## 9.4 验收标准

1. 每次小测包含后台配置的题目。
2. 用户未完成所有题目时不能提交。
3. 最终结果由服务端计算。
4. 前端提交正确率无效。
5. 每次提交只生成一条小测结果。
6. 重复请求不会生成重复记录。
7. 错题自动加入错题本。
8. 答对题目不能加入错题本。
9. 结果页正确展示用户答案。
10. 结果页正确展示标准答案。
11. 结果页正确展示解析。
12. 重新测试后生成新的独立记录。
13. 小测达到及格分数后章节完成状态正确更新。
14. 未达到及格分数时保留小测记录并允许再次测试。

## 12.4 得分公式

答对：

```text
100基础分 + 剩余整秒数 × 5
```

答错或超时：

```text
0分
```

## 12.5 积分规则

```text
初始积分：1000
胜利：+20
失败：-10
平局：0
中途退出：-10
系统异常：0
```

积分不得低于0。

## 12.6 核心接口

```text
POST /api/battles/start
GET  /api/battles/:battleId
POST /api/battles/:battleId/answer
POST /api/battles/:battleId/quit
GET  /api/battles/:battleId/result
GET  /api/battles/history
```

## 12.7 验收标准

1. 每局固定5题。
2. 同局题目不重复。
3. 每题倒计时15秒。
4. 超时答案记为错误。
5. 同一题不能重复提交。
6. 服务端计算最终分数。
7. 前端伪造分数无效。
8. 胜负判断符合规则。
9. 平分时按正确题数判断。
10. 正确题数相同时按总时间判断。
11. 完全相同时为平局。
12. 积分更新正确。
13. 积分不能为负数。
