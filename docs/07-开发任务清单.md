# 1. 文档目的

本文档用于将码站先锋 V1.0 MVP 拆分为可以逐项执行、逐项测试、逐项提交的开发任务。

每个任务都应具备：

1. 唯一任务编号。
2. 明确任务目标。
3. 前置任务。
4. 允许修改范围。
5. 核心产出。
6. 验收标准。
7. 建议Git提交信息。
8. 当前任务状态。

后续开发过程中，原则上按照本文档顺序执行。

如果出现新的需求，不应直接插入代码，应先增加或调整任务。

# 2. 任务状态说明

所有任务统一使用以下状态：

```text
TODO：尚未开始
READY：前置条件已满足，可以执行
IN_PROGRESS：正在由Codex执行
BLOCKED：存在阻断问题
REVIEW：Codex已完成，等待审查
TESTING：正在手工验收
DONE：已经验收并完成Git提交
CANCELLED：任务取消
```

状态流转：

```text
TODO
→ READY
→ IN_PROGRESS
→ REVIEW
→ TESTING
→ DONE
```

如果出现问题：

```text
IN_PROGRESS或REVIEW
→ BLOCKED
→ 修复后重新进入IN_PROGRESS
```

# 3. 任务执行总原则

## 3.1 单任务执行

同一时间只执行一个主要开发任务。

不建议同时让Codex开发：

* 后端课程模块。
* 管理后台课程页面。
* 小程序课程页面。

正确方式是：

```text
先完成后端基础
→ 再完成接口
→ 再完成前端调用
→ 再联调
```

## 3.2 一个任务一个提交

一个任务完成并验收后，建议创建一个Git提交。

示例：

```text
feat(health): add backend health check
```

## 3.3 未验收不进入下一任务

以下任何一项未完成，都不进入下一任务：

* 代码不能启动。
* 编译失败。
* 测试失败。
* 存在严重报错。
* 修改范围异常。
* 存在真实密钥。
* 手工验收未完成。
* Git未提交。

## 3.4 数据库任务额外要求

涉及数据库的任务必须：

* 修改 Prisma Schema。
* 生成迁移。
* 执行迁移。
* 生成 Prisma Client。
* 检查表结构。
* 更新Seed或说明不需要更新。
* 提交迁移文件。

| Phase 0  | 产品与技术设计  | 完成需求、页面、数据库、接口和规范 |

# 19. 任务依赖规则

## 19.1 后端优先

业务页面开发前，至少应完成对应后端接口。

例如：

```text
COURSE-004完成
→ MINIAPP-002开始
```

## 19.2 数据库优先

后端业务接口前，必须完成相关数据库模型。

例如：

```text
DATABASE-004完成
→ QUESTION-001开始
```

## 19.3 管理端内容优先

用户端依赖内容时，应先保证后台或Seed可以创建内容。

例如：

```text
课程后台基础可用
→ 添加测试课程
→ 小程序课程页面联调
```

## 19.4 核心闭环优先

如果时间或精力有限，优先完成：

```text
认证
课程
章节
小测
错题
练习
人机对战
```

社区和部分后台功能可以后置。
