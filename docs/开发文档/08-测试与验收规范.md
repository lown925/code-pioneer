# 1. 文档目的

本文档用于明确码站先锋 V1.0 MVP 的测试范围、测试方法、验收标准、Bug分级和上线阻断条件。

本文档重点解决以下问题：

1. Codex完成代码后应该检查什么。
2. 哪些命令必须运行。
3. 如何判断接口是否真实可用。
4. 如何测试微信小程序页面。
5. 如何测试管理后台。
6. 如何检查数据库数据是否正确。
7. 如何识别重复提交、越权和数据错误。
8. Bug严重程度如何划分。
9. 哪些问题必须修复后才能进入下一任务。
10. 用户作为开发新手应如何记录和反馈问题。

# 2. 测试基本原则

## 2.1 测试不是只看页面

功能完成不能只依据：

```text
页面能打开
按钮能点击
Codex说已经完成
```

必须同时检查：

* 页面交互。
* 后端接口。
* 数据库记录。
* 权限。
* 异常情况。
* 重复提交。
* 数据一致性。
* 重新进入页面后的状态。

## 2.2 先小范围，再全流程

每个任务完成后先测试当前模块。

阶段完成后再测试完整业务流程。

例如：

```text
先测试课程列表接口
→ 再测试课程详情
→ 再测试章节学习
→ 最后测试完整课程学习流程
```

## 2.3 正常与异常都要测试

每个核心功能至少测试：

```text
正常操作
参数错误
未登录
无权限
资源不存在
重复提交
网络失败
内容已下架
```

## 2.4 测试必须可复现

Bug记录必须包含：

* 操作环境。
* 前置条件。
* 操作步骤。
* 实际结果。
* 预期结果。
* 截图或日志。
* 是否必现。

不能只记录：

```text
这里好像有问题
```

## 2.5 测试失败不进入下一任务

出现以下情况时，当前任务不得标记为 `DONE`：

* 构建失败。
* 核心测试失败。
* 页面无法正常使用。
* 数据写入错误。
* 权限失效。
* 存在严重越权。
* 重复提交造成重复数据。
* 敏感信息泄漏。
* 存在P0或P1 Bug。

# 3. 测试层级

码站先锋采用以下测试层级：

```text
静态检查
→ 单元测试
→ 集成测试
→ 接口测试
→ 页面测试
→ 数据库检查
→ E2E流程测试
→ 回归测试
→ 真机测试
```

# 4. 静态检查

## 4.1 目的

在运行程序前，先发现：

* 语法错误。
* 类型错误。
* 格式问题。
* 未使用变量。
* 错误导入。
* 构建问题。

## 4.2 后端检查

根据项目脚本执行：

```bash
cd server
npm run lint
npm run build
```

如配置独立类型检查：

```bash
npm run typecheck
```

预期结果：

* 命令正常结束。
* 无编译错误。
* 无阻断级Lint错误。

## 4.3 管理后台检查

```bash
cd admin-web
npm run lint
npm run build
```

如有类型检查：

```bash
npm run typecheck
```

## 4.4 小程序检查

使用微信开发者工具执行：

* 编译。
* 代码质量检查。
* 控制台错误检查。

验收要求：

* 无红色编译错误。
* 无持续出现的运行异常。
* 无明显资源路径错误。

# 5. 单元测试

## 5.1 目的

单元测试用于验证单个Service、函数或业务规则。

重点测试：

* 计分公式。
* 胜负判断。
* 积分变化。
* 进度计算。
* 参数转换。
* 状态判断。
* 敏感词处理。

## 5.2 后端单元测试命令

```bash
cd server
npm test
```

指定模块：

```bash
npm test -- battles
```

持续监听模式不用于最终验收。

最终验收应使用一次性执行模式。

## 5.3 必测业务规则

### 对战计分

```text
答对：
100 + 剩余整秒 × 5

答错：
0

超时：
0
```

### 对战积分

```text
胜利：+20
失败：-10
平局：0
退出：-10
系统异常：0
最低积分：0
```

### 学习进度

```text
已完成章节数 ÷ 已发布章节数 × 100%
```

### 错题规则

```text
同一用户 + 同一道题
只能存在一条错题记录
```

### 点赞规则

```text
同一用户 + 同一帖子
只能存在一条点赞记录
```

# 6. 集成测试

## 6.1 目的

验证多个组件一起工作时是否正确。

例如：

```text
Controller
+ Service
+ Prisma
+ 数据库
+ Guard
```

## 6.2 重点场景

* 用户登录后访问受保护接口。
* 创建课程后写入数据库。
* 小测提交后生成答案记录和错题。
* 对战结算后更新用户积分。
* 点赞后同时更新点赞记录和数量。
* 举报处理后同时更新内容和举报状态。

## 6.3 测试数据库

集成测试必须使用独立测试数据库。

建议环境变量：

```text
DATABASE_URL_TEST
```

禁止使用正式数据库执行自动测试。

# 7. E2E测试

## 7.1 目的

E2E测试从HTTP入口验证完整业务流程。

## 7.2 建议命令

```bash
cd server
npm run test:e2e
```

## 7.3 核心E2E场景

至少覆盖：

1. 管理员登录。
2. 创建课程。
3. 创建章节。
4. 创建题目。
5. 发布章节和课程。
6. 用户登录。
7. 用户开始课程。
8. 用户完成小测。
9. 错题生成。
10. 创建练习。
11. 提交练习答案。
12. 创建人机对战。
13. 完成对战。
14. 发帖。
15. 评论。
16. 点赞。
17. 举报。
18. 管理员处理举报。

## 7.4 E2E测试隔离

测试执行前后需要：

* 初始化测试数据。
* 使用唯一测试标识。
* 清理测试数据。
* 不污染开发和正式环境。

# 8. 接口手工测试

## 8.1 推荐工具

可以使用：

* Swagger。
* VS Code REST Client。
* Postman。
* 浏览器，仅限GET接口。
* 小程序真实调用。

对新手而言，第一阶段优先使用Swagger。

## 8.2 Swagger地址

开发环境建议：

```text
http://localhost:3000/api/docs
```

## 8.3 接口测试记录

每个接口至少记录：

| 项目      | 内容            |
| ------- | ------------- |
| 请求方法    | GET、POST等     |
| 接口路径    | `/api/v1/...` |
| 是否需要登录  | 是或否           |
| 请求参数    | 实际提交内容        |
| HTTP状态码 | 200、400等      |
| 返回结果    | 成功或错误         |
| 数据库变化   | 有或无           |
| 测试结论    | 通过或失败         |

# 9. 通用接口验收

每个接口应测试以下情况。

## 9.1 正常请求

检查：

* 状态码正确。
* `success`为true。
* 返回字段符合接口文档。
* `requestId`存在。
* 数据库变化正确。

## 9.2 参数缺失

例如缺少必填字段。

预期：

* 返回400。
* 返回明确字段错误。
* 数据库不产生记录。

## 9.3 参数类型错误

例如：

```json
{
  "questionCount": "five"
}
```

预期：

* DTO校验失败。
* 不进入业务逻辑。

## 9.4 多余字段

如果全局配置：

```text
forbidNonWhitelisted: true
```

提交未定义字段时应被拒绝。

## 9.5 未登录

访问受保护接口。

预期：

* HTTP 401。
* 错误码为 `UNAUTHORIZED` 或 `ACCESS_TOKEN_INVALID`。

## 9.6 无权限

普通用户访问管理员接口。

预期：

* HTTP 403。
* 不返回后台数据。

## 9.7 资源不存在

预期：

* HTTP 404。
* 错误码明确。
* 不暴露数据库异常。

## 9.8 重复提交

使用同一幂等ID重复提交。

预期：

* 不生成重复数据。
* 不重复计分。
* 返回原结果或稳定当前状态。

# 10. 数据库验收方法

## 10.1 推荐工具

可以使用：

```bash
npx prisma studio
```

启动后在浏览器查看数据表。

也可以使用Sealos数据库管理工具或PostgreSQL客户端。

## 10.2 需要检查的内容

### 用户

* 同一Mock用户是否只创建一个账号。
* 默认积分是否为1000。
* 状态是否为NORMAL。

### 课程

* 课程和章节关系是否正确。
* 草稿是否不会出现在公开接口。
* 下架内容是否仍保留在后台。

### 学习记录

* 同一用户同一课程只有一条记录。
* 同一用户同一章节只有一条记录。
* 最近学习时间是否更新。
* 进度是否正确。

### 小测

* 小测提交后只生成一条Attempt。
* 每道题只生成一条Answer。
* 历史快照是否保存。
* 错题是否生成。

### 对战

* 一局是否固定5题。
* 题目是否重复。
* 每题是否只有一条用户答案。
* 积分是否只更新一次。
* `ratingBefore`和`ratingAfter`是否正确。

### 社区

* 重复点赞是否只有一条记录。
* 帖子点赞数是否正确。
* 删除帖子是否为软删除。
* 隐藏帖子是否不会出现在公开列表。

# 11. 数据一致性测试

## 11.1 学习进度一致性

操作：

1. 创建一门含4章的课程。
2. 完成1章。
3. 查看课程进度。

预期：

```text
25%
```

完成2章后：

```text
50%
```

重复完成同一章后仍应为：

```text
50%
```

## 11.2 错题一致性

操作：

1. 同一道题答错一次。
2. 再次答错。
3. 查看错题本。

预期：

* 只有一条错题记录。
* `wrongCount`为2。

## 11.3 点赞一致性

操作：

1. 点赞帖子。
2. 重复点击点赞。
3. 刷新页面。
4. 取消点赞。
5. 再次取消。

预期：

* 点赞数最多增加1。
* 取消后最多减少1。
* 不出现负数。

## 11.4 对战积分一致性

操作：

1. 记录对战前积分。
2. 完成一局胜利对战。
3. 多次刷新结果页。
4. 重复请求结果接口。

预期：

* 积分只增加20。
* 不因刷新重复增加。

## 11.5 评论数量一致性

操作：

1. 创建评论。
2. 重复提交同一幂等请求。
3. 删除评论。

预期：

* 只创建一条评论。
* 评论数增加1。
* 删除后减少1。
* 不出现负数。

# 12. 权限与越权测试

## 12.1 用户访问他人数据

准备用户A和用户B。

使用用户A令牌尝试访问用户B的：

* 小测结果。
* 练习结果。
* 对战结果。
* 错题记录。
* 反馈。
* 收藏。

预期：

```text
403或404
```

不应返回用户B数据。

## 12.2 删除他人内容

用户A尝试删除用户B的：

* 帖子。
* 评论。

预期：

* 删除失败。
* 数据不变化。

## 12.3 普通用户访问后台

使用普通用户令牌访问：

```text
/api/v1/admin/users
```

预期：

```text
403
```

## 12.4 内容管理员越权

内容管理员尝试：

* 创建超级管理员。
* 禁用超级管理员。
* 查看管理员管理页面。
* 查看仅超级管理员可见日志。

预期：

```text
403
```

## 12.5 禁用用户

用户被管理员禁用后测试：

* 发帖。
* 评论。
* 点赞。
* 对战。
* 小测。

预期：

* 受保护业务被拒绝。
* 公开内容仍可浏览。

# 13. 安全测试

## 13.1 敏感字段

检查所有用户与管理员接口，不得返回：

* openId。
* unionId。
* passwordHash。
* refreshTokenHash。
* AppSecret。
* 数据库连接地址。
* 对象存储密钥。

## 13.2 日志

故意触发登录错误和接口异常。

检查日志中不得出现：

* 密码。
* 完整Token。
* AppSecret。
* 数据库密码。

## 13.3 文件上传

测试：

* 正常PNG。
* 正常JPG。
* 超大图片。
* 文本文件伪装成PNG。
* 可执行文件。
* 空文件。
* 重复文件名。
* 超过数量限制。

预期：

* 非法文件被拒绝。
* 文件名被重新生成。
* 不覆盖旧文件。
* 不暴露存储密钥。

## 13.4 接口限流

测试：

* 高频管理员登录。
* 高频发布帖子。
* 高频评论。
* 高频举报。

预期：

* 达到限制后返回429。
* 正常使用不受明显影响。

# 15. 小程序通用测试

## 15.1 底部导航

测试：

* 首页。
* 对战。
* 互助。
* 我的。

预期：

* 可以正常切换。
* 选中状态正确。

## 15.2 登录拦截

未登录点击：

* 小测。
* 对战。
* 错题本。
* 发布帖子。
* 评论。
* 点赞。

预期：

* 出现登录提示。

## 15.4 Token过期

使用失效令牌。

预期：

* 提示重新登录。
* 不出现无限重试。
* 不重复弹出大量提示。

# 18. 小测页面验收

## 开始小测

检查：

* 题目数量正确。
* 不返回答案。
* 选项显示正确。

## 作答

检查：

* 可以切换题目。
* 未提交前可以修改。
* 未完成所有题目不能提交。
* 未答题号提示明确。

## 提交

检查：

* 提交中按钮禁用。
* 重复点击不重复生成记录。
* 失败后保留答案。
* 成功后进入结果页。

## 结果页

检查：

* 正确数。
* 错误数。
* 正确率。
* 用户答案。
* 正确答案。
* 解析。
* 错题本。
* 再测一次。

# 19. 错题本验收

检查：

# 20. 练习模式验收

## 设置页

检查：

* 课程选择。
* 章节选择。
* 5题和10题。
* 是否计时。
* 题库不足提示。

## 答题页

检查：

* 同局不重复。
* 每题只能提交一次。
* 计时模式倒计时正确。
* 超时自动提交。
* 非计时模式无倒计时。
* 提交后显示解析。

## 结果页

检查：

* 正确数和错误数正确。
* 总用时正确。

# 27. Bug严重程度

## P0 致命问题

定义：

* 系统无法启动。
* 数据库严重损坏。
* 大量数据丢失。
* 严重权限越权。
* 密钥泄漏。
* 用户可以修改他人核心数据。
* 对战积分可无限刷取。
* 正式环境无法访问。

处理要求：

```text
立即停止后续开发或上线
必须优先修复
```

## P1 严重问题

定义：

* 核心功能不可用。
* 无法登录。
* 无法学习。
* 无法提交小测。
* 无法完成对战。
* 重复提交造成明显重复数据。
* 积分结算错误。
* 管理员无法发布内容。

处理要求：

```text
当前阶段不得验收
上线前必须修复
```

## P2 一般问题

定义：

* 部分功能异常。
* 筛选不正确。
* 错误提示不清晰。
* 某些异常情况处理不完善。
* 局部页面错位。

处理要求：

* 原则上当前阶段修复。
* 不阻断核心流程时可记录后集中处理。

## P3 轻微问题

定义：

* 文案不够自然。
* 间距轻微不一致。
* 非核心动画问题。
* 不影响使用的小体验问题。

处理要求：

* 记录。
* UI优化阶段处理。
