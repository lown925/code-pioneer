## 课时 1：文件与文件描述符

课时简介：文件系统把持久数据组织为文件；进程通常通过文件描述符引用已打开对象。

预计学习时间：20 分钟

### 正文

[标题]
文件与文件描述符：先看系统状态，再看机制

[文本]
文件系统把持久数据组织为文件；进程通常通过文件描述符引用已打开对象。 学习这一课时，重点不是孤立背名词，而是明确“谁保存状态、谁改变状态、变化发生在哪个层次”。这样才能把硬件行为和操作系统抽象联系起来。

边界与工程判断

[文本]

预计学习时间：20 分钟

### 正文

[标题]
从 read 系统调用到设备：先看系统状态，再看机制

[文本]
一次 read 可能经历用户态调用、内核文件系统、页缓存、块层、驱动和设备，再把数据返回应用。 学习这一课时，重点不是孤立背名词，而是明确“谁保存状态、谁改变状态、变化发生在哪个层次”。这样才能把硬件行为和操作系统抽象联系起来。

[/代码]

[标题]
边界与工程判断

[文本]
系统调用只是完整 I/O 路径的入口之一。在分析题或真实故障中，应先固定初始条件，再沿数据路径或控制路径逐步推导；不能因为某个部件“通常更快”或“通常这样实现”，就把实现习惯误当成体系结构保证。

[示例 title=从 read 系统调用到设备分析示例]
说明：假设系统状态已经给定，先判断当前层次负责什么，再判断下一步状态变化。
语言：text

[/示例]

[提示 title=从 read 系统调用到设备学习提示]
缓存命中时可能无需访问物理磁盘。做题时把“定义”“机制”“性能影响”分开判断，通常能排除绝对化选项。

[警告 title=不要混淆抽象与具体实现]
课程中的 Python 片段仅用于表达算法或状态转换，不代表底层系统由 Python 实现。不同 CPU、操作系统和文件系统可以采用不同实现，只要满足相应接口与语义。
