## 课时 1：二进制与位权

课时简介：从十进制熟悉的“个位十位”理解二进制。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
计算机硬件天然适合区分两种稳定状态，所以最基础表示使用 0 和 1。难点不是背二进制，而是理解每一位也有“位权”。

[标题]
先建立一个能看见的模型

[文本]
十进制 352 = 3×100 + 5×10 + 2×1。二进制同理，只是位权变成 1、2、4、8、16……。因此 `1011₂ = 8 + 0 + 2 + 1 = 11`。

[代码 language=text]
二进制：1 0 1 1
位权： 8 4 2 1
计算： 8 + 0 + 2 + 1 = 11
[/代码]

[文本]
从右到左第 0 位权重是 2⁰=1，第 1 位是 2¹=2。把“每一位乘自己的位权再相加”作为固定方法，比直接背转换表更可靠。

[示例 title=最小可验证示例]
说明：用最小输入观察本课核心规则。
语言：text

二进制：1 0 1 1
位权： 8 4 2 1
计算： 8 + 0 + 2 + 1 = 11
[/示例]

[警告 title=常见错误]
把二进制 1011 当成十进制“一千零十一”。二进制位必须按 2 的幂解释。

[标题]
本课小结

[文本]

## 课时 3：无符号数与有符号数

课时简介：同样 8 个比特，为什么既能表示 0~255，也能表示负数？
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
位数有限意味着可表示范围有限。是否允许负数，取决于我们怎样解释最高位和整个比特模式。

[标题]
先建立一个能看见的模型

[文本]
8 位无符号数有 2^8=256 种模式，范围 0~255。若采用常见的二进制补码表示 8 位有符号整数，同样 256 种模式被分配给 -128~127。

[代码 language=text]
8 bit unsigned: 00000000 = 0      ... 11111111 = 255
8 bit signed:   01111111 = 127
                10000000 = -128
                11111111 = -1
[/代码]

[文本]
关键不是“最高位永远是符号位”这句话，而是整数类型规定了这 8 位按什么规则解释。硬件加法器可以处理同一位模式，软件类型决定我们怎样理解结果。

[示例 title=最小可验证示例]
说明：用最小输入观察本课核心规则。
语言：text

8 bit signed:   01111111 = 127
                10000000 = -128
                11111111 = -1
[/示例]

[警告 title=常见错误]
认为 8 位有符号整数范围是 -127~127，从而只有 255 个值。补码有 256 个模式，范围不对称。

[标题]

[文本]

## 课时 4：补码为什么方便加减法

课时简介：理解负数编码与加法器统一。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
如果硬件为正数加法、负数加法、减法各做一套复杂电路，成本很高。补码让“减去一个数”可以转成“加上它的补码”。

[标题]
先建立一个能看见的模型

[文本]
以 8 位为例，5 是 00000101。-5 的补码可由按位取反再加 1 得到：11111010 +1 =11111011。计算 7+(-5) 时，8 位加法后丢弃最高进位，得到 00000010，也就是 2。

[代码 language=text]
  00000111   (7)
+ 11111011   (-5)
-----------
1 00000010
丢弃第9位 → 00000010 = 2
[/代码]

[文本]
补码最重要的直觉是模 2^n 运算。位数固定时，超过范围的高位会被丢弃，因此正负数能共享同一加法硬件。

[示例 title=最小可验证示例]
说明：用最小输入观察本课核心规则。
语言：text

  00000111   (7)
+ 11111011   (-5)
-----------
1 00000010
丢弃第9位 → 00000010 = 2
[/示例]

[警告 title=常见错误]
把“取反加一”当作任何数都要做的步骤。只有求负数补码时才这样从对应正数得到负值编码。

[标题]

[文本]

## 课时 6：溢出与表示范围

课时简介：理解“数学结果正确”不代表“固定宽度机器结果可表示”。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
8 位寄存器只有 256 种模式。即使数学上 250+10=260，8 位无符号数也无法表示 260。

[标题]
先建立一个能看见的模型

[文本]
8 位无符号计算 `250 + 10`：250=11111010，10=00001010，相加得到 1 00000100。只有8位时最高进位被丢弃，结果变成 00000100=4。这就是无符号溢出的模 256 行为。

[代码 language=text]
  11111010  (250)
+ 00001010  (10)
-----------
1 00000100
保留8位 → 4
[/代码]

[文本]
有符号补码也会溢出，例如 100+50 数学上150，但8位有符号最大127。判断有符号溢出不能只看“有没有进位”，需要看结果是否超出类型范围。

[示例 title=最小可验证示例]
说明：用最小输入观察本课核心规则。
语言：text

- 能把 8 位以内的无符号二进制转换为十进制。
- 能完成十进制与二进制的双向转换并自检。
- 能根据位数计算无符号与补码有符号整数的范围。
- 能手算小范围补码并验证简单加减法。
- 能解释字符编码与字节序各自解决的问题。
- 能根据位宽判断是否溢出并解释截断后的结果。
