## 课时 1：寄存器、Cache、内存、磁盘的层次

课时简介：理解为什么系统使用多层而不是一种“又快又大又便宜”的存储。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
越快的存储通常越贵、越小。系统通过层次结构让最常用数据靠近CPU，把不常用数据放到更大更慢的位置。

[标题]
先建立一个能看见的模型

[文本]
典型层次是寄存器→L1/L2/L3 Cache→主存→SSD。CPU希望大部分访问命中靠近自己的层，从而获得“接近高速存储的速度”和“接近大容量存储的容量”。

[代码 language=text]
快/小/贵
寄存器
  ↓
L1/L2/L3 Cache
  ↓
主存 RAM
  ↓
SSD / 磁盘
慢/大/便宜
[/代码]

[文本]
每向下一层访问，延迟显著增加。后面Cache机制的目标就是提高上层命中率。

慢/大/便宜

## 课时 2：局部性为什么让 Cache 有效

课时简介：理解程序访问并不是完全随机。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
如果CPU下一次访问地址完全随机，Cache很难预测什么值得保留。幸运的是程序通常具有时间局部性和空间局部性。

[标题]
先建立一个能看见的模型

[文本]
时间局部性：刚访问过的数据很可能很快再次访问，例如循环变量。空间局部性：访问某地址后，很可能访问附近地址，例如顺序遍历数组。Cache利用这两点保留最近数据，并按块带入邻近字节。

[代码 language=text]
for i=0..99:
    sum += a[i]

空间局部性：a[0],a[1],a[2]...连续
时间局部性：sum 每轮都再次使用
[/代码]

[文本]
顺序遍历数组通常Cache友好；在巨大数组中随机跳跃访问更容易产生miss。

[示例 title=最小可验证示例]
说明：用最小输入观察本课核心规则。
语言：text

    sum += a[i]

空间局部性：a[0],a[1],a[2]...连续
时间局部性：sum 每轮都再次使用
[/示例]

## 课时 3：Cache line 与命中、未命中

课时简介：理解Cache不是按“单个变量”搬运，而常按固定块。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
从主存读取一个字节的成本很高，所以Cache通常一次搬一整条cache line，例如64字节。之后访问同一条内邻近数据就可能命中。

[标题]
先建立一个能看见的模型

[文本]
假设line=64字节，地址0~63在同一line。第一次访问地址0发生miss并载入0~63；接着访问地址4、8往往命中。访问地址64则属于下一条line。

[代码 language=text]
Cache line 大小 = 64B
Line 0: 地址 0..63
Line 1: 地址 64..127

访问 0 → miss，载入0..63
访问 4 → hit
访问64 → 新line，可能miss
[/代码]

[文本]
命中率高并不意味着每次只取一个值；整line搬运正是利用空间局部性。

## 课时 4：直接映射与冲突直觉

课时简介：理解不同内存块为什么会“争同一个Cache位置”。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
Cache容量有限。直接映射Cache规定每个内存块只能放到一个固定槽位，查找简单，但不同块可能映射到同一槽互相替换。

[标题]
先建立一个能看见的模型

[文本]
假设Cache有4个槽，块号使用 `block % 4` 选择槽。块0和块4都映射槽0。访问序列0,4,0,4会不断互相踢出，即使Cache其他槽空着，也会产生冲突miss。

[代码 language=text]
slot = block_number % 4
block0 → slot0
block4 → slot0
block8 → slot0

访问0,4,0,4 → 反复替换
[/代码]

[文本]
组相联Cache允许一个块在一组中的多个位置，能减少这种冲突，但硬件更复杂。

[示例 title=最小可验证示例]
说明：用最小输入观察本课核心规则。
语言：text

block0 → slot0
block4 → slot0
block8 → slot0

访问0,4,0,4 → 反复替换
[/示例]

[警告 title=常见错误]

## 课时 5：写回和写直达

课时简介：理解CPU修改Cache后，主存何时同步。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
读Cache只要找数据；写操作还要决定主存是否立即更新。两种基本策略是write-through和write-back。

[标题]
先建立一个能看见的模型

[文本]
write-through：每次写Cache同时写主存，主存较新但写流量大。write-back：先只改Cache并标记dirty，等该line被替换时再写回主存，减少流量但管理更复杂。

[代码 language=text]
Write-through:
CPU写 → Cache更新 + 主存立即更新

Write-back:
CPU写 → Cache更新 + dirty=1
替换时 → 主存更新
[/代码]

[文本]
write-back不等于“永远不写主存”。当脏line被替换或需要同步时必须写回。

说明：用最小输入观察本课核心规则。

CPU写 → Cache更新 + 主存立即更新

Write-back:
CPU写 → Cache更新 + dirty=1
替换时 → 主存更新
[/示例]

[警告 title=常见错误]
把write-back理解成程序结束后数据才写磁盘。这里讨论CPU Cache与主存的一致更新策略，不是文件持久化。

[文本]

[代码 language=text]

[/代码]

[文本]
如果序列改成0,1,0，第三次0会hit。做题时不要靠“最近见过”判断，还要看期间是否被冲突块替换。
