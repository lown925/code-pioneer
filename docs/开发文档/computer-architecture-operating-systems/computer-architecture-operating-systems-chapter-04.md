## 课时 1：CPU 数据通路

课时简介：数据通路连接寄存器、ALU、总线和其他功能单元，控制信号决定每一步的数据流向。

预计学习时间：20 分钟

### 正文

[标题]
CPU 数据通路：先看系统状态，再看机制

[文本]
数据通路连接寄存器、ALU、总线和其他功能单元，控制信号决定每一步的数据流向。 学习这一课时，重点不是孤立背名词，而是明确“谁保存状态、谁改变状态、变化发生在哪个层次”。这样才能把硬件行为和操作系统抽象联系起来。

[代码 language=python]
# 用伪代码表达本课的状态关系，不依赖具体运行环境
alu_out = left + right
[/代码]

[标题]
边界与工程判断

[文本]
数据通路负责承载和变换数据。在分析题或真实故障中，应先固定初始条件，再沿数据路径或控制路径逐步推导；不能因为某个部件“通常更快”或“通常这样实现”，就把实现习惯误当成体系结构保证。

[示例 title=CPU 数据通路分析示例]
说明：假设系统状态已经给定，先判断当前层次负责什么，再判断下一步状态变化。
语言：text
输入状态 -> 当前机制 -> 状态变化 -> 对上层可见结果
[/示例]

[提示 title=CPU 数据通路学习提示]
控制器决定哪些通路在何时生效。做题时把“定义”“机制”“性能影响”分开判断，通常能排除绝对化选项。

[警告 title=不要混淆抽象与具体实现]
课程中的 Python 片段仅用于表达算法或状态转换，不代表底层系统由 Python 实现。不同 CPU、操作系统和文件系统可以采用不同实现，只要满足相应接口与语义。

预计学习时间：20 分钟

### 正文

[标题]
数据冒险与转发：先看系统状态，再看机制

[文本]
后续指令依赖前序结果时会出现数据冒险，可通过转发或停顿保证读取到正确值。 学习这一课时，重点不是孤立背名词，而是明确“谁保存状态、谁改变状态、变化发生在哪个层次”。这样才能把硬件行为和操作系统抽象联系起来。

[/代码]

[标题]
边界与工程判断

[文本]
冒险处理首先保证语义正确。在分析题或真实故障中，应先固定初始条件，再沿数据路径或控制路径逐步推导；不能因为某个部件“通常更快”或“通常这样实现”，就把实现习惯误当成体系结构保证。

[/示例]

[提示 title=数据冒险与转发学习提示]
转发能减少部分不必要停顿。做题时把“定义”“机制”“性能影响”分开判断，通常能排除绝对化选项。
