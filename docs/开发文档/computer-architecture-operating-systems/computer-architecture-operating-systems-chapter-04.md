## 课时 1：数据通路与控制信号

课时简介：理解“执行一条指令”其实是让数据沿硬件路径移动。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
CPU 不是一个黑盒。寄存器、ALU、选择器和总线组成数据通路；控制器发出信号决定这一步让谁读、谁算、谁写。

[标题]
先建立一个能看见的模型

[文本]
执行 `ADD R1,R2,R3` 时，需要从寄存器堆读出R2/R3，送进ALU做加法，再把ALU输出写回R1。控制信号会选择ALU操作为ADD并使能R1写入。

[代码 language=text]
R2 ─┐
    ├→ ALU(ADD) → result → 写回 R1
R3 ─┘
控制：ALUop=ADD, RegWrite=1, Dest=R1
[/代码]

[文本]
数据通路回答“数据从哪到哪”，控制信号回答“这次允许什么动作”。把两者分开理解，后面流水线和冒险会清晰很多。

    ├→ ALU(ADD) → result → 写回 R1
R3 ─┘
控制：ALUop=ADD, RegWrite=1, Dest=R1
[/示例]

[警告 title=常见错误]
把控制器当作“负责所有计算”的部件。真正算术逻辑通常由ALU完成，控制器决定路径和时序。

## 课时 2：ALU 和寄存器之间怎样传数据

课时简介：理解读取、计算、写回三个阶段的数据依赖。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
很多CPU题之所以难，是因为同一个寄存器既可能作为输入又可能是输出。必须明确“读发生在旧值，写回产生新值”。

[标题]
先建立一个能看见的模型

[文本]
若执行 `ADD R1,R1,R2`，开始时R1=4,R2=3。ALU读取旧R1=4和R2=3得到7，随后写回R1=7。不能在计算中一边读一边把R1当成已经是7。

[代码 language=text]
执行前：R1=4, R2=3
读取：4 和 3
ALU：4+3=7
写回：R1=7
[/代码]

[文本]
状态题坚持“先读输入，算结果，再写回”就不容易混淆。实际硬件通过时钟边沿和组合逻辑保证这种阶段关系。

[/示例]

## 课时 3：单周期与多周期执行直觉

课时简介：理解“时钟周期”与指令总时间不是一回事。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
如果所有指令必须在一个时钟周期完成，周期必须长到足够容纳最慢指令；简单ADD也要等同样久。多周期设计则把工作拆成几个更短阶段。

[标题]
先建立一个能看见的模型

[文本]
简化地看，LOAD可能需要取指、译码、地址计算、访存、写回；ADD不需要数据内存访问。单周期设计让两者都塞进一个长周期，多周期允许按步骤使用硬件。

[代码 language=text]
LOAD: IF → ID → EX(算地址) → MEM → WB
ADD : IF → ID → EX(加法) → WB
[/代码]

[文本]
多周期并不自动意味着“每条都更快”；它改变的是硬件复用和时钟周期设计。后续流水线进一步让不同指令的不同阶段重叠。

说明：用最小输入观察本课核心规则。
语言：text

LOAD: IF → ID → EX(算地址) → MEM → WB
ADD : IF → ID → EX(加法) → WB
[/示例]

把“多周期”理解为一定比“单周期”慢，因为周期数更多。比较性能还要看单个时钟周期长度。

## 课时 4：流水线分阶段

课时简介：用“洗衣流水线”直觉理解多条指令重叠。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
一条指令的取指阶段结束后，取指硬件可以服务下一条，而第一条进入译码。让不同指令同时处于不同阶段，可以提高吞吐量。

[标题]
先建立一个能看见的模型

[文本]
假设5级流水线 IF/ID/EX/MEM/WB。第1周期I1在IF；第2周期I1在ID、I2在IF；填满后理想情况下每周期都能完成一条指令。单条指令延迟未必变成1周期，但总体吞吐提高。

[代码 language=text]
周期: 1   2   3   4   5   6
I1:   IF  ID  EX  MEM WB
I2:       IF  ID  EX  MEM WB
I3:           IF  ID  EX  MEM WB
[/代码]

[文本]
流水线的价值类似工厂流水线：不是让一辆车瞬间造完，而是让不同工位同时加工不同车辆。

I1:   IF  ID  EX  MEM WB
I2:       IF  ID  EX  MEM WB
I3:           IF  ID  EX  MEM WB
[/示例]

## 课时 5：数据相关与暂停

课时简介：理解为什么后一条指令有时不能马上用前一条结果。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
流水线重叠带来新问题：I2可能在I1还没写回时就需要I1的结果。这叫数据相关。

[标题]
先建立一个能看见的模型

[文本]
I1: `ADD R1,R2,R3`；I2: `SUB R4,R1,R5`。I2依赖I1产生的新R1。如果硬件支持 forwarding，可以把ALU结果直接旁路给I2；否则可能插入bubble暂停等待。

[代码 language=text]
I1: ADD R1,R2,R3   ← 产生 R1
I2: SUB R4,R1,R5   ← 立即使用 R1
          ↑ RAW 依赖
[/代码]

[文本]
RAW（read after write）是最直观的数据相关：后指令要读前指令尚未完成的新值。旁路能解决很多情况，但某些load-use依赖仍可能需要暂停。

          ↑ RAW 依赖
[/示例]

[警告 title=常见错误]
只要两条指令都提到R1就认为一定冲突。要看谁读、谁写以及执行时间。

## 课时 6：分支为什么会打断流水线

课时简介：理解控制相关：CPU尚未知道下一条到底在哪。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
遇到 `if` 或循环跳转时，CPU必须等条件结果才能确定PC。流水线却已经可能把顺序路径的几条指令取进来了。

[标题]
先建立一个能看见的模型

[文本]
如果预测“分支不跳转”，CPU继续取顺序指令；后来发现实际要跳转，已经进入流水线的错误路径指令必须丢弃并从目标地址重新取。这叫分支误预测代价。

[代码 language=text]
if (x==0) goto L1

预测：不跳 → 先取 A,B
实际：跳到 L1
结果：A,B 作废，流水线重新从 L1 取指
[/代码]

[文本]
现代CPU使用分支预测减少等待，但预测不可能100%正确。程序中难预测的分支可能带来性能损失。

[示例 title=最小可验证示例]
说明：用最小输入观察本课核心规则。
语言：text

预测：不跳 → 先取 A,B
实际：跳到 L1
结果：A,B 作废，流水线重新从 L1 取指
[/示例]

[提示 title=判断自己是不是真的理解]
把示例中的数字、名称或输入换掉，再独立推导一次。如果还能解释每一步，说明你理解的是规则而不是答案。

[警告 title=常见错误]
以为错误路径指令已经取进来就一定会修改程序状态。现代流水线会在确认前避免错误提交，误预测时清除。

[标题]
本课小结

[文本]
能解释分支预测、误预测和流水线清空的基本过程。
