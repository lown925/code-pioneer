## 课时 1：机器指令由哪些字段组成

课时简介：从“CPU 怎么知道做什么”理解操作码和操作数。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
机器指令是一串位，但 CPU 需要从中区分“做什么操作”和“数据从哪来”。这就需要约定指令格式。

[标题]
先建立一个能看见的模型

[文本]
简化指令可以写成 `ADD R1, R2, R3`：操作码 ADD 表示加法，源寄存器 R2/R3 提供数据，目标寄存器 R1 保存结果。真实机器会把这些字段编码进固定位段。

[代码 language=text]
ADD R1, R2, R3
含义：R1 ← R2 + R3

操作码：ADD
目标：R1
源：R2, R3
[/代码]

[文本]
如果执行前 R2=7、R3=5，执行后 R1=12，而 R2/R3 通常不因为读取自动改变。读题时必须区分源和目标。

## 课时 2：寄存器为什么比内存更近

课时简介：理解 CPU 为什么不能每次都从主存取临时值。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
CPU 执行速度很高，而主存访问更慢。把最常用的操作数放在 CPU 内部寄存器，可以减少等待。

[标题]
先建立一个能看见的模型

[文本]
例如计算 `(a+b)*c`，编译器可能把 a、b、c 先装入寄存器，再完成加法和乘法，最后把结果写回内存。寄存器数量很少，所以只适合当前最急用的数据。

[代码 language=text]
LOAD R1, [a]
LOAD R2, [b]
ADD  R3, R1, R2
LOAD R4, [c]
MUL  R5, R3, R4
STORE [result], R5
[/代码]

[文本]
寄存器不是“更小的硬盘”，而是 CPU 数据通路直接使用的高速存储。寄存器少且昂贵，内存容量大但更慢。

## 课时 3：取指、译码、执行循环

课时简介：理解 CPU 不停重复的基本节拍。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
程序在内存里排成指令序列。CPU 必须知道下一条在哪里、这串位表示什么、然后真正执行。

[标题]
先建立一个能看见的模型

[文本]
最基本循环可以分为：取指 fetch——根据程序计数器 PC 从内存取下一条指令；译码 decode——识别操作码和字段；执行 execute——让 ALU、寄存器或访存单元完成动作；随后 PC 更新到下一条。

[代码 language=text]
PC=100
  ↓ Fetch: 取地址100的指令
Decode: ADD R1,R2,R3
Execute: R1←R2+R3
  ↓
PC=104（假设每条4字节）
[/代码]

[文本]
普通顺序执行时 PC 通常前进；跳转、函数调用或异常会改变 PC，使下一条指令来自不同地址。PC 是理解控制流的关键。

Execute: R1←R2+R3
  ↓
PC=104（假设每条4字节）
[/示例]

## 课时 4：寻址方式与操作数来源

课时简介：理解“7”可能是立即数，也可能是地址或寄存器内容。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
同一条加法需要的数据可能直接写在指令里、位于寄存器、或位于内存地址。寻址方式告诉 CPU 到哪里取真正操作数。

[标题]
先建立一个能看见的模型

[文本]
例如 `MOV R1, 7` 中 7 是立即数；`MOV R1, R2` 从寄存器取；`LOAD R1, [1000]` 把内存地址1000处的数据读入 R1。方括号常用来表示“取这个地址里的内容”。

[代码 language=text]
立即数： MOV R1, 7      → R1=7
寄存器： MOV R1, R2     → R1=R2当前值
内存：   LOAD R1,[1000] → R1=内存[1000]
[/代码]

[文本]
区分“地址”和“地址中的值”特别重要。如果内存[1000]=42，那么 `1000` 是位置，`[1000]` 表示从这个位置取到42。

## 课时 5：函数调用与栈的直觉

课时简介：理解为什么函数调用后还能回到原位置。
预计学习时间：12-18 分钟

### 正文

[标题]
为什么现在需要它

[文本]
函数调用会暂时跳到另一段代码执行，但执行完必须知道回到哪里；函数里的局部变量也需要有自己的存储空间。栈非常适合这种后进先出的调用结构。

[标题]
先建立一个能看见的模型

[文本]
调用 `main → foo → bar` 时，bar 最后调用却最先返回。每次调用会建立一个栈帧，保存返回地址、部分局部变量或寄存器。bar 返回后弹出自己的帧，再回到 foo。

[代码 language=text]
栈顶
[ bar 栈帧 | 返回 foo ]
[ foo 栈帧 | 返回 main]
[main 栈帧 ]
栈底
[/代码]

[文本]
这解释了递归为什么会不断消耗栈空间：每一层调用都需要保留自己的返回现场。过深递归可能发生栈溢出。

[示例 title=最小可验证示例]
说明：用最小输入观察本课核心规则。
语言：text

栈顶
[ bar 栈帧 | 返回 foo ]
[ foo 栈帧 | 返回 main]
[main 栈帧 ]
栈底
[/示例]

[警告 title=常见错误]
认为所有局部变量都永远在栈上。优化编译器可能放寄存器，某些对象在堆上；这里先理解“调用上下文用栈管理”的模型。
