## 课时 1：机器指令的基本组成

课时简介：一条机器指令通常编码操作类型以及源、目的操作数的位置。

预计学习时间：20 分钟

### 正文

[标题]
机器指令的基本组成：先看系统状态，再看机制

[文本]
一条机器指令通常编码操作类型以及源、目的操作数的位置。 学习这一课时，重点不是孤立背名词，而是明确“谁保存状态、谁改变状态、变化发生在哪个层次”。这样才能把硬件行为和操作系统抽象联系起来。

[代码 language=python]
# 用伪代码表达本课的状态关系，不依赖具体运行环境
instruction = {'op': 'ADD', 'dst': 'R1', 'src': 'R2'}
[/代码]

[标题]
边界与工程判断

[文本]
指令编码必须能让处理器确定操作与操作数。在分析题或真实故障中，应先固定初始条件，再沿数据路径或控制路径逐步推导；不能因为某个部件“通常更快”或“通常这样实现”，就把实现习惯误当成体系结构保证。

[示例 title=机器指令的基本组成分析示例]
说明：假设系统状态已经给定，先判断当前层次负责什么，再判断下一步状态变化。
语言：text
输入状态 -> 当前机制 -> 状态变化 -> 对上层可见结果
[/示例]

[提示 title=机器指令的基本组成学习提示]
不同 ISA 的指令格式可以不同。做题时把“定义”“机制”“性能影响”分开判断，通常能排除绝对化选项。

[警告 title=不要混淆抽象与具体实现]
课程中的 Python 片段仅用于表达算法或状态转换，不代表底层系统由 Python 实现。不同 CPU、操作系统和文件系统可以采用不同实现，只要满足相应接口与语义。

预计学习时间：20 分钟

### 正文

[标题]
函数调用与栈帧：先看系统状态，再看机制

[文本]
函数调用需要保存返回地址、参数、局部变量及必要寄存器，调用约定规定双方责任。 学习这一课时，重点不是孤立背名词，而是明确“谁保存状态、谁改变状态、变化发生在哪个层次”。这样才能把硬件行为和操作系统抽象联系起来。

[/代码]

[标题]
边界与工程判断

[文本]
调用约定保证不同函数能够可靠协作。在分析题或真实故障中，应先固定初始条件，再沿数据路径或控制路径逐步推导；不能因为某个部件“通常更快”或“通常这样实现”，就把实现习惯误当成体系结构保证。

[/示例]

[提示 title=函数调用与栈帧学习提示]
