## 课时 1：软件工程的目标

课时简介：学习 软件工程的目标 的核心思想、工程边界和项目实践方式。

预计学习时间：20 分钟

### 正文

[标题]
软件工程的目标

[文本]
建立软件生命周期、需求、设计、开发、测试、交付与维护的整体认识。 本课重点是把软件开发从“写代码”扩展到完整工程过程。需要同时考虑需求是否明确、设计是否可维护、协作是否顺畅、测试是否覆盖关键风险，以及最终交付是否可验证。

[示例 title=软件工程的目标工程示例]
语言：text
目标 -> 约束 -> 方案 -> 实现 -> 验证 -> 反馈
[/示例]

[提示 title=工程思维]
做软件工程题时，先问三个问题：要解决什么问题？谁会受影响？如何证明结果满足要求？

[警告 title=不要把流程当形式]
流程、文档和工具只有在降低风险、提升协作和保障质量时才有价值。不要为了“看起来规范”而制造无意义步骤。

### 课时题目

#### 题目 1

题型：SINGLE_CHOICE
题干：关于“软件工程的目标”，下列哪种做法最符合软件工程思想？
难度：EASY
分值：10
知识点：软件工程的目标
是否用于 Battle：否

选项：
- A. 先明确目标、约束与验收方式，再选择合适的实现方法 [正确]
- B. 只要功能能运行，就不需要测试和维护
- C. 所有项目都应使用完全相同的流程
- D. 文档越多就一定代表工程质量越高

解析：
软件工程强调在约束下持续交付可验证的软件价值，而不是只关注代码是否暂时能运行。

#### 题目 2

题型：SINGLE_CHOICE
题干：团队在“软件工程的目标”相关环节出现返工。哪种改进最合理？
难度：MEDIUM
分值：10
知识点：软件工程的目标、项目协作
是否用于 Battle：是
Battle 难度：MEDIUM
Battle 展示类型：场景判断

选项：
- A. 明确输入输出、责任人和验收条件，并让关键变化可追踪 [正确]
- B. 减少所有沟通，让每个人独立决定接口
- C. 删除测试以缩短开发时间
- D. 每次出现问题都直接推翻全部架构

解析：
返工通常来自边界、责任或验收不清。建立可追踪契约和验证方式比增加无意义流程更有效。

#### 题目 3

题型：SINGLE_CHOICE
题干：某项目在“软件工程的目标”环节为了赶进度跳过验证，短期交付成功但后续故障频发。最合理的改进是什么？
难度：HARD
分值：10
知识点：软件工程的目标、质量管理
是否用于 Battle：是
Battle 难度：HARD
Battle 展示类型：工程判断

选项：
- A. 在关键风险点加入自动化验证和明确验收门禁，并保留可回退路径 [正确]
- B. 继续跳过测试，只增加开发人数
- C. 每次失败后直接删除历史版本
- D. 让所有成员拥有生产环境最高权限

解析：
工程质量依赖可重复验证、风险控制和恢复能力。短期速度不能以失去可控性为代价。

[警告 title=不要把流程当形式]
流程、文档和工具只有在降低风险、提升协作和保障质量时才有价值。不要为了“看起来规范”而制造无意义步骤。

### 课时题目

#### 题目 16

题型：SINGLE_CHOICE
题干：关于“项目风险与技术债”，下列哪种做法最符合软件工程思想？
难度：EASY
分值：10
知识点：项目风险与技术债
是否用于 Battle：否

选项：
- A. 先明确目标、约束与验收方式，再选择合适的实现方法 [正确]
- B. 只要功能能运行，就不需要测试和维护
- C. 所有项目都应使用完全相同的流程
- D. 文档越多就一定代表工程质量越高

解析：
软件工程强调在约束下持续交付可验证的软件价值，而不是只关注代码是否暂时能运行。

#### 题目 17

题型：SINGLE_CHOICE
题干：团队在“项目风险与技术债”相关环节出现返工。哪种改进最合理？
难度：MEDIUM
分值：10
知识点：项目风险与技术债、项目协作
是否用于 Battle：是
Battle 难度：MEDIUM
Battle 展示类型：场景判断

选项：
- A. 明确输入输出、责任人和验收条件，并让关键变化可追踪 [正确]
- B. 减少所有沟通，让每个人独立决定接口
- C. 删除测试以缩短开发时间
- D. 每次出现问题都直接推翻全部架构

解析：
返工通常来自边界、责任或验收不清。建立可追踪契约和验证方式比增加无意义流程更有效。

#### 题目 18

题型：CODE_FILL
题干：补全下面用于表达“项目风险与技术债”工程逻辑的伪代码，使流程成立。填写 `____`。
难度：HARD
分值：10
知识点：项目风险与技术债、工程流程
是否用于 Battle：是
Battle 难度：HARD
Battle 展示类型：代码填空

题目代码:
```python
risk_score = probability * ____
```

可接受答案:
```text
impact
```

判题设置：
- 区分大小写：是
- 忽略首尾空格：是
- 保留代码内部空格：否
- 统一 Windows 和 Unix 换行：是

解析：
缺失部分应为 `impact`。代码用简化形式表达工程流程，重点是理解步骤与责任关系。

标准完整代码:
```python
risk_score = probability * impact
```
