## 课时 1：机密性、完整性与认证

课时简介：学习 机密性、完整性与认证 的核心概念、机制、边界与诊断方法。

预计学习时间：20 分钟

### 正文

[标题]
机密性、完整性与认证

[文本]
理解认证、加密、完整性、常见网络攻击及基本防护边界。 本课围绕“机密性、完整性与认证”展开。分析网络问题时，要明确通信双方、协议层次、报文状态和设备职责，避免把不同层的地址、连接或故障原因混为一谈。

[示例 title=机密性、完整性与认证场景]
语言：text
发送端 -> 协议处理 -> 网络传输 -> 接收端
观察点：地址、状态、报文、时延与错误位置
[/示例]

[提示 title=分析方法]
先确定问题发生在哪一层，再沿封装、转发或连接状态逐步检查。协议提供的是规则和语义，具体性能还取决于链路、设备、负载和实现。

[警告 title=不要跨层混淆]
IP 地址、MAC 地址、端口号和应用名称承担不同职责；某一层正常并不代表端到端通信一定正常。

### 课时题目

#### 题目 145

题型：SINGLE_CHOICE
题干：关于“机密性、完整性与认证”，下列哪项分析方式最合理？
难度：EASY
分值：10
知识点：机密性、完整性与认证
是否用于 Battle：否

选项：
- A. 先确定协议层次和当前状态，再判断该机制负责解决的问题 [正确]
- B. 所有网络故障都可以归因于带宽不足
- C. IP 地址、MAC 地址和端口号可以互相替代
- D. 只要局域网可达，应用服务就一定正常

解析：
网络分析首先要确定层次、状态和职责，不能用单一指标解释所有端到端问题。

#### 题目 146

题型：SINGLE_CHOICE
题干：排查“机密性、完整性与认证”相关问题时，哪种做法更符合分层网络的诊断原则？
难度：MEDIUM
分值：10
知识点：机密性、完整性与认证、网络诊断
是否用于 Battle：是
Battle 难度：MEDIUM
Battle 展示类型：场景判断

选项：
- A. 从已知正常边界开始，逐层验证地址、报文或连接状态 [正确]
- B. 不检查报文和状态，直接更换所有网络设备
- C. 默认所有协议层使用同一种地址
- D. 只观察应用界面，不检查底层连接

解析：
分层诊断通过逐步缩小故障边界提高判断可靠性。

#### 题目 147

题型：SINGLE_CHOICE
题干：某网络在“机密性、完整性与认证”相关环节出现异常。为什么不能仅凭“链路有连接”就断定端到端服务正常？
难度：HARD
分值：10
知识点：机密性、完整性与认证、端到端分析
是否用于 Battle：是
Battle 难度：HARD
Battle 展示类型：综合判断

选项：
- A. 端到端通信还依赖其他协议层的寻址、状态、转发和应用服务 [正确]
- B. 因为物理链路与网络完全没有关系
- C. 因为网络中不存在分层协议
- D. 因为所有应用都必须使用相同端口

解析：

理解认证、加密、完整性、常见网络攻击及基本防护边界。 本课围绕“防火墙与最小权限”展开。分析网络问题时，要明确通信双方、协议层次、报文状态和设备职责，避免把不同层的地址、连接或故障原因混为一谈。

[示例 title=防火墙与最小权限场景]
语言：text
发送端 -> 协议处理 -> 网络传输 -> 接收端
观察点：地址、状态、报文、时延与错误位置
[/示例]

[提示 title=分析方法]
先确定问题发生在哪一层，再沿封装、转发或连接状态逐步检查。协议提供的是规则和语义，具体性能还取决于链路、设备、负载和实现。

[警告 title=不要跨层混淆]
IP 地址、MAC 地址、端口号和应用名称承担不同职责；某一层正常并不代表端到端通信一定正常。

选项：
- A. 先确定协议层次和当前状态，再判断该机制负责解决的问题 [正确]
