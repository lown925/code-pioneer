## 课时 1：网络边缘与核心

课时简介：学习 网络边缘与核心 的核心概念、机制、边界与诊断方法。

预计学习时间：20 分钟

### 正文

[标题]
网络边缘与核心

[文本]
建立端系统、链路、交换设备、协议与分层模型的整体认识。 本课围绕“网络边缘与核心”展开。分析网络问题时，要明确通信双方、协议层次、报文状态和设备职责，避免把不同层的地址、连接或故障原因混为一谈。

[示例 title=网络边缘与核心场景]
语言：text
发送端 -> 协议处理 -> 网络传输 -> 接收端
观察点：地址、状态、报文、时延与错误位置
[/示例]

[提示 title=分析方法]
先确定问题发生在哪一层，再沿封装、转发或连接状态逐步检查。协议提供的是规则和语义，具体性能还取决于链路、设备、负载和实现。

[警告 title=不要跨层混淆]
IP 地址、MAC 地址、端口号和应用名称承担不同职责；某一层正常并不代表端到端通信一定正常。

### 课时题目

#### 题目 1

题型：SINGLE_CHOICE
题干：关于“网络边缘与核心”，下列哪项分析方式最合理？
难度：EASY
分值：10
知识点：网络边缘与核心
是否用于 Battle：否

选项：
- A. 先确定协议层次和当前状态，再判断该机制负责解决的问题 [正确]
- B. 所有网络故障都可以归因于带宽不足
- C. IP 地址、MAC 地址和端口号可以互相替代
- D. 只要局域网可达，应用服务就一定正常

解析：
网络分析首先要确定层次、状态和职责，不能用单一指标解释所有端到端问题。

#### 题目 2

题型：SINGLE_CHOICE
题干：排查“网络边缘与核心”相关问题时，哪种做法更符合分层网络的诊断原则？
难度：MEDIUM
分值：10
知识点：网络边缘与核心、网络诊断
是否用于 Battle：是
Battle 难度：MEDIUM
Battle 展示类型：场景判断

选项：
- A. 从已知正常边界开始，逐层验证地址、报文或连接状态 [正确]
- B. 不检查报文和状态，直接更换所有网络设备
- C. 默认所有协议层使用同一种地址
- D. 只观察应用界面，不检查底层连接

解析：
分层诊断通过逐步缩小故障边界提高判断可靠性。

#### 题目 3

题型：SINGLE_CHOICE
题干：某网络在“网络边缘与核心”相关环节出现异常。为什么不能仅凭“链路有连接”就断定端到端服务正常？
难度：HARD
分值：10
知识点：网络边缘与核心、端到端分析
是否用于 Battle：是
Battle 难度：HARD
Battle 展示类型：综合判断

选项：
- A. 端到端通信还依赖其他协议层的寻址、状态、转发和应用服务 [正确]
- B. 因为物理链路与网络完全没有关系
- C. 因为网络中不存在分层协议
- D. 因为所有应用都必须使用相同端口

解析：
链路只是完整通信路径的一部分。可靠结论需要结合相关协议层和端点状态。

端到端通信路径

[文本]
建立端系统、链路、交换设备、协议与分层模型的整体认识。 本课围绕“端到端通信路径”展开。分析网络问题时，要明确通信双方、协议层次、报文状态和设备职责，避免把不同层的地址、连接或故障原因混为一谈。

[示例 title=端到端通信路径场景]
语言：text
发送端 -> 协议处理 -> 网络传输 -> 接收端
观察点：地址、状态、报文、时延与错误位置
[/示例]

[提示 title=分析方法]
先确定问题发生在哪一层，再沿封装、转发或连接状态逐步检查。协议提供的是规则和语义，具体性能还取决于链路、设备、负载和实现。

[警告 title=不要跨层混淆]
IP 地址、MAC 地址、端口号和应用名称承担不同职责；某一层正常并不代表端到端通信一定正常。

题型：SINGLE_CHOICE
题干：关于“端到端通信路径”，下列哪项分析方式最合理？
难度：EASY
分值：10
知识点：端到端通信路径
是否用于 Battle：否

选项：
- A. 先确定协议层次和当前状态，再判断该机制负责解决的问题 [正确]
- B. 所有网络故障都可以归因于带宽不足
- C. IP 地址、MAC 地址和端口号可以互相替代

网络分析首先要确定层次、状态和职责，不能用单一指标解释所有端到端问题。

#### 题目 18

题型：CODE_FILL
题干：补全下面用于表达“端到端通信路径”网络状态处理的代码，使示例成立。填写 `____`。
难度：HARD
分值：10
知识点：端到端通信路径、网络状态
是否用于 Battle：是
Battle 难度：HARD
Battle 展示类型：代码填空

题目代码:
```python
port = socket.htons(____)
```

可接受答案:
```text
443
```

判题设置：
- 区分大小写：是
- 忽略首尾空格：是
- 保留代码内部空格：否
- 统一 Windows 和 Unix 换行：是

解析：
填入 `443` 后，代码形成完整的网络状态处理表达。代码用于帮助理解协议机制，不代表协议只能用 Python 实现。

标准完整代码:
```python
port = socket.htons(443)
```
