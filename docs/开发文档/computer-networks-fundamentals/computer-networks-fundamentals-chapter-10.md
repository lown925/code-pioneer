## 课时 1：Socket 通信模型

课时简介：学习 Socket 通信模型 的核心概念、机制、边界与诊断方法。

预计学习时间：20 分钟

### 正文

[标题]
Socket 通信模型

[文本]
通过 Socket、抓包和常见诊断工具串联完整网络通信路径。 本课围绕“Socket 通信模型”展开。分析网络问题时，要明确通信双方、协议层次、报文状态和设备职责，避免把不同层的地址、连接或故障原因混为一谈。

[示例 title=Socket 通信模型场景]
语言：text
发送端 -> 协议处理 -> 网络传输 -> 接收端
观察点：地址、状态、报文、时延与错误位置
[/示例]

[提示 title=分析方法]
先确定问题发生在哪一层，再沿封装、转发或连接状态逐步检查。协议提供的是规则和语义，具体性能还取决于链路、设备、负载和实现。

[警告 title=不要跨层混淆]
IP 地址、MAC 地址、端口号和应用名称承担不同职责；某一层正常并不代表端到端通信一定正常。

### 课时题目

#### 题目 163

题型：SINGLE_CHOICE
题干：关于“Socket 通信模型”，下列哪项分析方式最合理？
难度：EASY
分值：10
知识点：Socket 通信模型
是否用于 Battle：否

选项：
- A. 先确定协议层次和当前状态，再判断该机制负责解决的问题 [正确]
- B. 所有网络故障都可以归因于带宽不足
- C. IP 地址、MAC 地址和端口号可以互相替代
- D. 只要局域网可达，应用服务就一定正常

解析：
网络分析首先要确定层次、状态和职责，不能用单一指标解释所有端到端问题。

题型：SINGLE_CHOICE

知识点：Socket 通信模型、网络诊断
是否用于 Battle：是
Battle 难度：MEDIUM
Battle 展示类型：场景判断

选项：
- A. 从已知正常边界开始，逐层验证地址、报文或连接状态 [正确]
- B. 不检查报文和状态，直接更换所有网络设备
- C. 默认所有协议层使用同一种地址
- D. 只观察应用界面，不检查底层连接

解析：
分层诊断通过逐步缩小故障边界提高判断可靠性。

#### 题目 165

难度：HARD
分值：10
知识点：Socket 通信模型、端到端分析
是否用于 Battle：是
Battle 难度：HARD

- B. 因为物理链路与网络完全没有关系
- C. 因为网络中不存在分层协议

解析：

通过 Socket、抓包和常见诊断工具串联完整网络通信路径。 本课围绕“从 URL 到页面的完整链路”展开。分析网络问题时，要明确通信双方、协议层次、报文状态和设备职责，避免把不同层的地址、连接或故障原因混为一谈。

[示例 title=从 URL 到页面的完整链路场景]
语言：text
发送端 -> 协议处理 -> 网络传输 -> 接收端
观察点：地址、状态、报文、时延与错误位置
[/示例]

[提示 title=分析方法]
先确定问题发生在哪一层，再沿封装、转发或连接状态逐步检查。协议提供的是规则和语义，具体性能还取决于链路、设备、负载和实现。

[警告 title=不要跨层混淆]
IP 地址、MAC 地址、端口号和应用名称承担不同职责；某一层正常并不代表端到端通信一定正常。

- A. 先确定协议层次和当前状态，再判断该机制负责解决的问题 [正确]
