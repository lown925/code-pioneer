## 课时 1：DNS 名称解析

课时简介：学习 DNS 名称解析 的核心概念、机制、边界与诊断方法。

预计学习时间：20 分钟

### 正文

[标题]
DNS 名称解析

[文本]
掌握 DNS、HTTP、HTTPS、电子邮件等典型应用层协议。 本课围绕“DNS 名称解析”展开。分析网络问题时，要明确通信双方、协议层次、报文状态和设备职责，避免把不同层的地址、连接或故障原因混为一谈。

[示例 title=DNS 名称解析场景]
语言：text
发送端 -> 协议处理 -> 网络传输 -> 接收端
观察点：地址、状态、报文、时延与错误位置
[/示例]

[提示 title=分析方法]
先确定问题发生在哪一层，再沿封装、转发或连接状态逐步检查。协议提供的是规则和语义，具体性能还取决于链路、设备、负载和实现。

[警告 title=不要跨层混淆]
IP 地址、MAC 地址、端口号和应用名称承担不同职责；某一层正常并不代表端到端通信一定正常。

### 课时题目

选项：
- A. 先确定协议层次和当前状态，再判断该机制负责解决的问题 [正确]
- B. 所有网络故障都可以归因于带宽不足
- C. IP 地址、MAC 地址和端口号可以互相替代
- D. 只要局域网可达，应用服务就一定正常

解析：
网络分析首先要确定层次、状态和职责，不能用单一指标解释所有端到端问题。

Battle 难度：MEDIUM

观察点：地址、状态、报文、时延与错误位置
[/示例]

[提示 title=分析方法]
先确定问题发生在哪一层，再沿封装、转发或连接状态逐步检查。协议提供的是规则和语义，具体性能还取决于链路、设备、负载和实现。

[警告 title=不要跨层混淆]
IP 地址、MAC 地址、端口号和应用名称承担不同职责；某一层正常并不代表端到端通信一定正常。
