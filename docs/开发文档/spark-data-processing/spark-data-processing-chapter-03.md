## 课时 1：Pair RDD

课时简介：从本章真实场景出发理解“Pair RDD”，并通过最小例子、步骤追踪、常见错误和练习建立可迁移的理解。
预计学习时间：12-18 分钟

### 正文

[标题]
先从一个真实问题开始

[文本]
本课要解决的是“Pair RDD”。不要先背定义。回到本章场景：统计单词次数、每个专业平均分，都需要把相同 key 的数据聚到一起；这通常会引入 shuffle。

如果把术语拿掉，学习这部分真正要回答三个问题：**为什么需要它、它改变了什么、怎样判断自己用对了**。

[标题]
把核心概念拆开

[文本]
Pair RDD并不是一个孤立名词。它和本章主题“键值 RDD 与聚合”直接相连。初学时可以先把它理解成解决当前问题的一种明确规则或结构：输入是什么、经过什么步骤、最后得到什么结果。

Spark API 很多，但真正决定性能和正确性的常常是分区、依赖、shuffle 和执行时机。先看数据怎样流动，再记 API。

[代码 language=scala]
val counts = sc.parallelize(Seq("a", "b", "a"))
  .map(word => (word, 1))
  .reduceByKey(_ + _)
[/代码]

[文本]
阅读上面的例子时，不要只看最后一行。请按顺序检查：第一步建立了什么数据或状态；第二步依据什么条件发生变化；第三步为什么能得到当前结果。只要这三步能解释清楚，就已经比“记住一个 API/术语”更接近真正理解。

[标题]
一步一步验证，而不是凭感觉

[文本]
遇到这类问题，可以固定使用下面的检查方法：

1. 写出当前已知的数据、状态或输入。
2. 只执行一个步骤，记录发生的变化。
3. 检查下一步依赖的是旧状态还是新状态。
4. 对照目标，确认最终结果是否满足要求。

这个方法看起来慢，但它能帮助初学者找到“自己到底从哪一步开始没看懂”。熟练以后，这些检查会逐渐在脑中自动完成。

[示例 title=把概念放回本章场景]
说明：先不追求复杂规模，只用最小输入验证“Pair RDD”的核心行为。
语言：scala

val counts = sc.parallelize(Seq("a", "b", "a"))
  .map(word => (word, 1))
  .reduceByKey(_ + _)
[/示例]

[提示 title=先解释结果，再记术语]
如果你能不用专业词解释“输入经过什么步骤变成了输出”，再去记术语通常会容易很多。术语是对已经理解的现象起名字，而不是理解本身。

[警告 title=不要把看起来合理当成真正理解]
这类知识最常见的误区是“我看答案觉得有道理”。真正掌握的标准是：换一组数据、换一个顺序或故意放一个错误，你仍然能推导出结果，并说明为什么。

[标题]
本课结束前检查自己

[文本]
完成本课后，你至少应该能回答：

- “Pair RDD”是在解决什么具体问题？
- 例子里的每一步输入和输出是什么？
- 如果删掉关键步骤，会出现什么错误或不同结果？
- 在什么情况下应该想到使用这一知识？
