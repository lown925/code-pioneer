## 课时 1：职责划分与类设计

课时简介：学习 职责划分与类设计 的核心概念、Java 写法与工程边界。

预计学习时间：20 分钟

### 正文

[标题]
职责划分与类设计

[文本]
把类设计、接口、集合、异常与 IO 组合成小型工程。 本课重点不是机械记语法，而是理解 Java 代码背后的对象职责、状态变化和 API 契约。编写代码时要明确数据归属、调用边界和异常情况。

[示例 title=职责划分与类设计示例]
语言：java
class Demo {
    public static void main(String[] args) {
        System.out.println("职责划分与类设计");
    }
}
[/示例]

[提示 title=学习方法]
先写清楚“对象负责什么”，再决定字段、方法和依赖关系。面向对象不是把所有逻辑都塞进类，而是用清晰职责组织代码。

[警告 title=工程边界]
示例以 Java 17+ 常见语法为主。不同项目版本可能限制语言特性；真实项目还应结合测试、异常处理、资源释放和线程安全要求。

### 课时题目

#### 题目 163

题型：SINGLE_CHOICE
题干：关于“职责划分与类设计”，下列哪种理解更符合 Java 面向对象设计原则？
难度：EASY
分值：10
知识点：职责划分与类设计
是否用于 Battle：否

选项：
- A. 先明确对象职责与状态，再选择合适的语法和 API [正确]
- B. 所有功能都应该写进一个类
- C. 只要代码能编译，就说明设计一定合理
- D. 所有字段都应该声明为 public

解析：
Java 语法服务于设计。可靠代码需要清晰职责、合理封装和可验证的状态变化。

#### 题目 164

题型：SINGLE_CHOICE
题干：在使用“职责划分与类设计”时，哪种做法更利于长期维护？
难度：MEDIUM
分值：10
知识点：职责划分与类设计、代码设计
是否用于 Battle：是
Battle 难度：MEDIUM
Battle 展示类型：场景判断

选项：
- A. 保持接口清晰、职责单一，并为异常和边界情况留出处理路径 [正确]
- B. 为减少文件数量，把所有类合并成一个类
- C. 忽略访问控制，让任何对象都能修改内部状态
- D. 依赖未说明的全局状态以缩短参数列表

解析：
长期可维护性依赖清晰边界、封装和可预测行为，而不是代码表面上的“短”。

#### 题目 165

题型：SINGLE_CHOICE
题干：某项目在“职责划分与类设计”相关设计中出现高耦合和难测试问题。下列哪种改进最合理？
难度：HARD
分值：10
知识点：职责划分与类设计、重构
是否用于 Battle：是
Battle 难度：HARD
Battle 展示类型：工程判断

选项：
- A. 重新划分职责、减少不必要依赖，并通过接口或封装稳定边界 [正确]
- B. 把更多字段改成 public 以方便直接访问
- C. 复制相同逻辑到多个类中避免调用

解析：
