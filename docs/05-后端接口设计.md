# 1. 文档目的

本文档用于明确码站先锋 V1.0 MVP 的后端接口规范，包括：

1. 接口统一前缀。
2. 请求与响应格式。
3. 登录鉴权方式。
4. 普通用户与管理员权限。
5. 分页规范。
6. 错误码规范。
7. 幂等规则。
8. 文件上传规则。
9. 各业务模块接口。
10. Codex开发和测试要求。

本文档是小程序前端、管理后台和后端开发之间的统一协议。

后续开发中，不允许前端和后端分别自行定义不同字段。

# 3. HTTP方法规范

## 3.1 GET

用于获取数据。

示例：

```text
GET /api/v1/courses
GET /api/v1/posts/:postId
```

GET请求不得修改业务数据。

## 3.2 POST

用于：

* 创建资源。
* 提交动作。
* 启动业务流程。

示例：

```text
POST /api/v1/chapters/:chapterId/quiz/submit
POST /api/v1/battles/:battleId/answers
```

## 3.3 PATCH

用于部分更新。

示例：

```text
PATCH /api/v1/users/me
PATCH /api/v1/users/me
```

## 3.4 PUT

第一版尽量少用。

只有完整替换资源时才使用。

## 3.5 DELETE

用于删除、取消或软删除。

示例：

```text
DELETE /api/v1/posts/:postId
DELETE /api/v1/posts/:postId/like
```

后端实际可执行软删除。

# 4. 请求头规范

## 4.1 通用请求头

```text
Content-Type: application/json
Accept: application/json
```

## 4.2 用户鉴权

```text
Authorization: Bearer <accessToken>
```

## 4.3 管理员鉴权

同样使用：

```text
Authorization: Bearer <adminAccessToken>
```

但普通用户令牌与管理员令牌必须包含不同身份类型。

建议令牌负载包含：

```json
{
  "sub": "账号ID",
  "tokenType": "USER",
  "sessionId": "会话ID",
  "role": "NORMAL"
}
```

管理员示例：

```json
{
  "sub": "管理员ID",
  "tokenType": "ADMIN",
  "role": "SUPER_ADMIN"
}
```

## 4.4 幂等请求头

需要幂等保护的接口使用：

```text
Idempotency-Key: 唯一请求标识
```

适用接口：

* 小测提交。
* 练习答案提交。
* 对战答案提交。
* 发布帖子。
* 提交评论。
* 提交举报。
* 提交反馈。

请求标识建议由前端生成 UUID。

# 5. 统一响应格式

## 5.1 成功响应

```json
{
  "success": true,
  "data": {},
  "message": "操作成功",
  "requestId": "请求追踪ID"
}
```

`message` 可选，但建议保留。

## 5.2 列表响应

```json
{
  "success": true,
  "data": {
    "items": [],
    "pagination": {
      "page": 1,
      "pageSize": 20,
      "total": 100,
      "totalPages": 5,
      "hasNext": true
    }
  },
  "requestId": "请求追踪ID"
}
```

## 5.3 失败响应

```json
{
  "success": false,
  "error": {
    "code": "INVALID_PARAMETER",
    "message": "参数错误",
    "details": [
      {
        "field": "title",
        "message": "标题长度不能少于5个字符"
      }
    ]
  },
  "requestId": "请求追踪ID"
}
```

## 5.4 安全要求

正式环境错误响应不得包含：

* 程序堆栈。
* SQL语句。
* 数据库地址。
* 系统文件路径。
* 内部密钥。
* Prisma内部错误详情。

# 6. HTTP状态码规范

| HTTP状态码 | 使用场景          |
| ------: | ------------- |
|     200 | 查询、更新、删除或动作成功 |
|     201 | 创建资源成功        |
|     400 | 请求参数错误        |
|     401 | 未登录、令牌无效或已过期  |
|     403 | 已登录但无权限       |
|     404 | 资源不存在或不可访问    |
|     409 | 数据冲突、重复操作     |
|     422 | 业务规则不满足       |
|     429 | 请求过于频繁        |
|     500 | 服务端内部错误       |
|     503 | 服务暂时不可用       |

示例：

* 未登录：401。
* 普通用户访问后台：403。
* 重复点赞：409或直接返回当前状态。
* 题库不足：422。
* 对战已结束仍提交答案：409。
* 系统异常：500或503。

# 8. 分页规范

## 8.1 请求参数

第一版统一使用页码分页：

```text
page
pageSize
```

默认值：

```text
page = 1
pageSize = 20
```

限制：

```text
page >= 1
1 <= pageSize <= 50
```

示例：

```text
GET /api/v1/posts?page=1&pageSize=20
```

## 8.2 排序参数

通用排序参数：

```text
sortBy
sortOrder
```

`sortOrder`：

```text
asc
desc
```

不是所有接口都允许任意字段排序。

后端必须使用允许列表，防止用户传入任意数据库字段。

## 8.3 列表稳定性

分页查询必须包含稳定排序。

例如帖子列表：

```text
createdAt DESC, id DESC
```

避免相同时间记录导致分页重复。

# 9. 日期与时间规范

1. 后端统一使用 ISO 8601 格式。
2. 返回时间使用 UTC。
3. 示例：

```text
2026-07-11T10:30:00.000Z
```

4. 前端负责转换为本地时间。
5. 不返回模糊格式，如：

```text
2026/7/11 18:30
```

---

# 10. 字段返回规则

## 10.1 ID

所有ID使用字符串返回。

## 10.2 Decimal

数据库 Decimal 字段建议在接口中返回数字或字符串，但全项目必须统一。

第一版建议：

```text
progressPercent 返回 number
accuracy 返回 number
```

范围：

```text
0 至 100
```

## 10.3 null与缺失字段

固定响应模型中的可选字段建议明确返回 `null`。

不得同一接口有时返回空字符串、有时返回 `null`。

## 10.4 敏感字段

任何普通接口不得返回：

* openId。
* unionId。
* passwordHash。
* refreshTokenHash。
* AppSecret。
* 管理员密码。
* 数据库字段中的内部密钥。

# 12. 普通用户认证接口

## 12.1 微信登录

```text
POST /api/v1/auth/wechat-login
```

权限：

```text
PUBLIC
```

请求：

```json
{
  "code": "微信临时登录凭证"
}
```

响应：

```json
{
  "success": true,
  "data": {
    "accessToken": "访问令牌",
    "refreshToken": "刷新令牌",
    "expiresIn": 7200,
    "user": {
      "id": "用户ID",
      "nickname": null,
      "avatarUrl": null,
      "status": "NORMAL",
      "experience": 0,
      "battleRating": 1000
    },
    "isNewUser": true
  }
}
```

规则：

1. `code` 必填。
2. 生产环境中，后端使用 `code` 调用微信 `code2Session` 换取身份。
3. 非生产环境且显式开启开发 Mock 配置时，同一个接口允许使用约定格式的 Mock `code`，由服务端生成确定性的模拟 `openId`。
4. Mock 登录只存在服务端实现，小程序始终调用同一个正式接口，不新增 `/api/v1/auth/mock-login`。
5. Mock 登录成功后仍必须创建或复用真实 `User`、`UserSession`，并签发正式 `accessToken` 与 `refreshToken`。
6. 同一 `openId` 不重复创建用户。
7. 被禁用用户返回 `USER_DISABLED`。
8. 已注销用户（`status=DELETED` 或 `deletedAt` 非空）一律返回 `USER_DELETED`，不恢复账号，不创建新用户，不创建新 `UserSession`。
9. AppSecret 只存在服务端环境变量。
10. 建议配置项名称统一为：

```text
AUTH_MOCK_ENABLED
WECHAT_APP_ID
WECHAT_APP_SECRET
JWT_ACCESS_SECRET
JWT_REFRESH_SECRET
JWT_ACCESS_EXPIRES_IN
JWT_REFRESH_EXPIRES_IN
```

11. `isNewUser=true` 仅在首次创建用户时返回，重复登录返回 `false`。
12. 响应中不得返回 `openId`、`unionId`、`session_key`。

## 12.2 刷新令牌

```text
POST /api/v1/auth/refresh
```

请求：

```json
{
  "refreshToken": "刷新令牌"
}
```

响应：

```json
{
  "success": true,
  "data": {
    "accessToken": "新访问令牌",
    "refreshToken": "新刷新令牌",
    "expiresIn": 7200
  }
}
```

规则：

1. `refreshToken` 必填。
2. 服务端必须校验令牌类型为刷新令牌，不得混用访问令牌。
3. 服务端必须根据令牌中的 `sub` 与 `sessionId` 定位 `User` 与 `UserSession`。
4. 仅未撤销、未过期且所属用户有效的会话允许刷新。
5. 刷新成功后执行 Refresh Token 轮换，并使旧刷新令牌立即失效。
6. 刷新成功后更新 `UserSession.lastUsedAt`。
7. 完整刷新令牌不得写入日志或明文入库。

## 12.3 退出登录

```text
POST /api/v1/auth/logout
```

权限：

```text
USER
```

作用：

* 撤销当前会话。
* 使刷新令牌失效。
* 访问令牌自然过期后不再允许继续刷新。

## 12.4 退出所有设备

```text
POST /api/v1/auth/logout-all
```

权限：

```text
USER
```

不属于当前 MVP 必做范围，保留为后续扩展接口。

# 13. 用户资料接口

## 13.1 更新个人资料

```text
PATCH /api/v1/users/me
```

权限：

```text
USER
```

请求：

```json
{
  "nickname": "码站学员",
  "avatarUrl": "https://cdn.example.com/avatar.png"
}
```

响应：

```json
{
  "success": true,
  "data": {
    "id": "用户ID",
    "nickname": "码站学员",
    "avatarUrl": "https://cdn.example.com/avatar.png",
    "status": "NORMAL",
    "experience": 120,
    "battleRating": 1040,
    "continuousLearningDays": 3,
    "lastLoginAt": "时间",
    "createdAt": "时间"
  }
}
```

校验：

* 昵称长度1至30。
* 不允许纯空格。
* 至少提供 `nickname` 或 `avatarUrl` 其中之一。
* `avatarUrl` 最大长度2048个字符。
* `avatarUrl` 必须是合法的 `https` URL。
* 不允许 `http:`、`data:`、`file:`、`javascript:`、`ftp:` 等协议。
* 当前阶段不验证 `FileAsset` 归属；`FileAsset` 模型落地后升级为平台上传资源归属校验。

## 13.2 个人数据概览

## 13.3 注销账号

```text
POST /api/v1/users/me/delete-account
```

权限：

```text
USER
```

请求：

```json
{
  "confirmation": "DELETE"
}
```

响应：

```json
{

  "data": {}
```

规则：

1. 必须二次确认。
2. 用户状态改为 `DELETED`。
3. 撤销该用户全部未撤销会话。
4. 对外昵称和头像可匿名化。
5. 不物理删除历史答题和对战记录。

## 16.2 开始学习章节

```text
POST /api/v1/chapters/:chapterId/start
```

权限：

```text
USER
```

作用：

* 创建或更新章节学习记录。
* 更新课程最近学习章节。
* 更新最近学习时间。
* 当前用户尚无 `CourseLearningRecord` 时自动创建课程学习记录。

规则：

1. 必须认证。
2. 章节必须存在且属于已发布、可学习的课程。
3. 当前用户尚无 `CourseLearningRecord` 时：
   * 自动创建课程学习记录；
   * `status=LEARNING`；
   * 写入 `startedAt`；
   * 写入 `lastLearnedAt`。
4. 当前用户已有课程学习记录时：
   * 不重复创建；
   * 已 `COMPLETED` 的课程不得回退为 `LEARNING`；

   * 创建章节学习记录；
   * `status=LEARNING`；
   * 写入 `firstStartedAt`；

   * 不重复创建；
   * 已 `COMPLETED` 的章节不得回退；
   * 更新 `lastLearnedAt`。

8. 接口不得更新 `completedAt`。

## 16.3 完成章节

```text
POST /api/v1/chapters/:chapterId/complete
```

权限：

```text
USER
```

规则：

1. 必须认证。
2. 章节及所属课程必须可访问。
3. 当前用户必须已有对应 `CourseLearningRecord`。
4. 当前用户必须已有对应 `ChapterLearningRecord`。
5. 尚未开始学习该章节时，不自动补建记录，返回业务错误。
6. 无小测章节可直接完成。
7. 有小测章节时：
   * 只有 `ChapterLearningRecord.quizCompleted = true` 才能完成；
   * 若当前阶段不存在可验证的小测通过记录，则必须返回明确错误，不得绕过。
8. 章节完成后：
   * `ChapterLearningRecord.status=COMPLETED`；
   * 首次完成时写入 `completedAt`；
   * 更新 `lastLearnedAt`。
9. 重复完成保持幂等：
   * 不重复创建记录；
   * `completedAt` 保留首次完成时间，不得重复刷新。
10. 在同一事务内重新计算课程进度：
    * `completedChapterCount`
    * `totalChapterCount`
    * `progressPercent`
    * `status`
    * `lastLearnedAt`
    * `completedAt`
11. 全部已发布章节完成时，课程记录变为 `COMPLETED` 且 `progressPercent=100`。
12. 未全部完成时，课程记录保持 `LEARNING` 且 `completedAt=null`。
13. 课程没有任何已发布章节时，不得自动完成课程，`progressPercent=0`。

可能错误：

```text
CHAPTER_NOT_STARTED
QUIZ_NOT_COMPLETED
CHAPTER_QUIZ_NOT_AVAILABLE
```

响应：

```json
{
  "success": true,
  "data": {
    "chapterStatus": "COMPLETED",
    "courseProgressPercent": 30,
    "nextChapterId": "下一章ID"
  }
}
```

说明：

* 本阶段学习进度采用章节完成型模型。
* 本阶段不实现独立章节百分比进度接口。
* 本阶段不实现 `learningSeconds`、播放位置或客户端上报学习时长。

* `courseCount`：至少包含一道当前用户错题的去重课程数量。
* `latestWrongAt`：最近一次错误作答所属 `QuizAttempt.submittedAt`，无错题时返回 `null`。

## 19.3 错题详情

```text

```

权限：

```text

```

规则：

1. `questionId` 必须是 UUID。
2. 只有当前用户历史上答错过该题才允许访问。
3. 当前用户从未答错该题，返回 `WRONG_QUESTION_NOT_FOUND`。
4. 题目存在但仅被其他用户答错，同样返回 `WRONG_QUESTION_NOT_FOUND`。
5. 详情允许返回正确答案和解析，因为属于当前用户本人复习页面。
6. 不返回每一次历史错误答案，也不返回其他用户数据。
7. 正确答案仅支持当前已正式落地的 `SINGLE_CHOICE` 与 `TRUE_FALSE`，由 `QuizOption.isCorrect=true` 唯一确定；若正确选项缺失、多于一个或数据不完整，返回 `QUIZ_NOT_READY`。

# 42. 鉴权与权限守卫

建议设计：

```text
JwtUserAuthGuard
JwtAdminAuthGuard
RolesGuard
OptionalUserAuthGuard
```

## 42.1 JwtUserAuthGuard

用于普通用户登录接口。

校验要求：

```text
Authorization: Bearer <accessToken>
tokenType 必须为 USER
sub 必须可定位有效用户
sessionId 必须可定位有效会话
```

以下情况统一返回 `401`：

* 访问令牌缺失或格式错误。
* 令牌已过期、签名无效或类型错误。
* 用户不存在、已禁用或已删除。
* 会话不存在、已撤销或已过期。

## 42.2 JwtAdminAuthGuard

用于管理员接口。

## 42.3 RolesGuard

用于限制：

```text
SUPER_ADMIN
CONTENT_ADMIN
```

## 42.4 OptionalUserAuthGuard

用于公开但登录后返回个性化数据的接口，例如：

* 首页。
* 课程列表。
* 课程详情。
* 帖子列表。
* 帖子详情。

令牌无效时建议返回401，而不是偷偷当作未登录处理。

无令牌时允许匿名继续访问；有令牌时必须按 `JwtUserAuthGuard` 的同等规则完成校验。

## 42.5 CurrentUser

用户鉴权通过后，控制器或服务层统一通过 `@CurrentUser()` 获取当前用户上下文。

建议结构：

```ts
{
  id: string;
  sessionId: string;
  tokenType: 'USER';
  role: 'NORMAL';
}
```

不得仅以 `nickname` 作为身份依据。
